## Context

规划稿给出 S1–S7 里程碑，但当前代码与规划存在结构性差距：

- `RouteFirstGenerator.cs`（676 行）单文件承载地形/行走/机关/诱饵/评分，评分是内联 7 维归一化 ×100，数学上限 100，到不了 180；
- 无独立指标提取器、无 `LevelTagger`、无 MAP-Elites、无 `StepCore`/`ResetToSpec`；
- 生成 180 seeds 只在 `CoreTests` 里跑并 `GD.Print`，**不落盘、无法 diff**；
- `tests/` 整个目录未入 git，黄金路线基线有丢失风险；
- 手工关卡是 `.tscn` 直编，没有导出成 `LevelSpec` 的通道，锚点无法实测。

因此先补验证基础设施（S0），再按「指标 → 结构重构 → 参数/尺寸 → 标签 → 分布 → 预算 → 接入」推进。

**已确认决策**

1. 每个里程碑停下验收（交付改动 + 验证命令 + 提交信息草稿）。
2. 尺寸上限 **20×20 全开**，按降级矩阵控制 C 类指标与求解预算。
3. 跑批 / spec dump / 基线快照作为**独立 S0**。
4. 同批修正 `coding-rules.md §12` 与 `qa.md` 中「禁止混入 C#」的过期条款。

**总原则**：S0–S6 全部只影响 `tools/` 与 `tests/`（`Generate`/`GenerateBand` 当前零调用点），游戏运行零风险；S7 才引入首个运行时调用点。

## S1 · 指标与评分基线

**新增**

| 文件 | 职责 |
| --- | --- |
| `Scripts/Algorithms/Scoring/MetricExtractor.cs` | 19 项指标，一次重放采样 A/B 类；C 类走有界搜索 |
| `Scripts/Algorithms/Scoring/ScoreSpline.cs` | 归一化 + `D_core`/`D_raw` 两段 + 锚点单调分段线性插值 |
| `Scripts/Algorithms/Scoring/ScoreAnchors.cs` | 加载/校验 `tests/fixtures/score_anchors.json` |
| `Scripts/Algorithms/Search/BoundedRouteEnumerator.cs` | 长度 ≤ S+2 的胜利路线有界枚举（DFS + visited + 节点预算） |

**修改**

- `RuleState.cs`：新增 internal `CaptureState/RestoreState`（trail、steps、maxLen、食物/遮挡掩码、机关等级与占格、finished）——这是有界枚举与 S2 `ResetToSpec` 的共同底座。
- `LevelSolution.cs`：`LevelScore` 扩展为 `Difficulty(0–200)/Quality/Metrics/Tags/TagEvidence/TargetScore/TargetMiss/ScoringVersion=2`。
- `ExactBfsSolver.cs`：食物掩码 >31 显式返回 UNKNOWN + `push_warning`（现在会静默溢出）。
- `CoreTests.cs`：指标手算单测 + 锚点回归 + 5 关 spec dump 读回断言。

**关键实现决策**

- **C 类不推迟**：`faN`(9) + `funnelN`(5) 进 `D_raw`，锚点按 `D_raw` 建，推迟会导致锚点/样条/快照重做两次。
- M14 `false_affordance`：对角逐诱饵做「禁格后重解」——若最优解 > S+2 或不可解，计为假捷径（≤2 次求解）。
- M16 `funnel_width`：有界枚举；超预算时 `c_estimated=1`，取已计数下界、权重贡献减半，并禁用依赖 C 的标签。全程不用墙钟。
- 锚点两段式：S1 先落 L1–L5 + A0（5/10/25/45/100/5）并让样条单调；`A6=180` 用上限档构造 spec 暂定；`A4.5` 留节点、S5 用真实批次中位数回填（暂定 70）。
- Top-K 默认 5（配置项），S1 用实测 `solve_exact` 耗时决定 5 或 10。

**Exit**

```powershell
& $G --headless --path . tests/core/CoreTests.tscn
```

- `score(L1)=5±2`、`L2=10±2`、`L3=25±3`、`L4=45±3`、`L5=100±2`；样条单调，倒挂即失败。
- 指标单测逐项与手算一致；180 seeds 能产出完整指标向量与直方图（不要求分布达标）。

3. 收尾一次重放断言 `eaten == F_req` 且无死锁，否则丢候选。

## S4 · 标签分类器（事后）

**新增** `Scripts/Algorithms/Scoring/LevelTagger.cs`：11 个标签判据 + `tag_evidence`（指标值/格坐标/步序）。

- 标签：`false_shortcut / gate_sequence / forced_truncation / overshoot_return / mirror_fork / mutual_exclusion / body_key / last_gasp / tight_budget / no_mechanism / dense_maze`。
- 分类只读 `LevelSpec` + 路线 + 指标向量；**生成路径不得出现标签判断**。
- C 类不可用时（`c_estimated=1`）不触发 `false_shortcut` / `mutual_exclusion`。

**Exit**

- 500 seeds 批次：5 个结构标签各自覆盖率 ≥ 5%（>40% 也视为旋钮过窄）；同一关重复分类结果一致；生成器代码 grep 不到 tag 引用。

**停点**：每种标签抽 3 关，你判断是否公平、线索是否可读。

## S5 · 分布控制

**新增**

- `Scripts/Algorithms/Scoring/TargetSampler.cs`：偏正态 `μ≈88, σ≈30, α≈2.0` + 拒绝采样（<20 或 >180 重采）。
- `Scripts/Algorithms/Generation/MapElitesArchive.cs`：按 `(尺寸, 步数桶, min_slack 桶, mech_pressure 桶)` 分格；选 `argmin |Difficulty - target|`，缺失回退最近格并记 `target_miss`。

**校准**

- 用 500 seeds 实测回填 `A4.5`（该段中位数，暂定 70）与 `A6`（上限档实测 D），重跑锚点快照与回归。
- 50–70 段占比 < 8% 记为不达标 KPI，回溯调旋钮采样范围，**禁止分位映射凑分布**。

**Exit**

- 500 seeds：§2.2 全部指标达标（主体区间 ≥95%、众数 75–85、中位数 82–92、均值 88–100、std 28–38、偏度 +0.4~+0.9、`P(<20)≤3%`、`P(>180)≤2%`、L5 分位 ≥70%）；直方图空洞 KPI 记录在汇总 JSON。

**停点**：你确认分布形态与 45–100 段是否仍有断层。
