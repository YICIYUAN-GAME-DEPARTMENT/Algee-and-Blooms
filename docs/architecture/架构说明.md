# 架构说明

> 配套主文档：[开发文档（权威）](../开发文档.md) §2。本文展开分层、Autoload、事件总线、场景编排等实现细节。
> 玩法规则与数值见 [功能需求文档（权威）](../design/功能需求文档.md)；本文件只讲"工程怎么搭"。

## 1. 分层职责

```
Autoload 单例（全局，跨场景存活）
   ├ GameManager      顶层状态/场景切换；持有 balance（Balance.tres 只读）
   ├ EventManager     信号总线（解耦）
   └ SaveManager      每关最佳步数存档（user://）
关卡脚本（每关一个 Level_<nn>.tscn，挂 Level.gd）
   ├ 逻辑：LevelState.gd（薄适配，转发 C# RuleState；不再含规则）
   ├ 表现：Level.gd（场景节点 / 动画 / HUD / 剧情 / 输入）
   └ 持有 GridSystem（场景网格数据：地板 / 障碍 / 实际占格）
实体（设计者直接摆进关卡场景/涂格的节点与图层）
   ├ Ground / Obstacles（TileMapLayer，涂格；障碍=被涂格，非实体）
   ├ PlayerSpawn / Food / Goal / Mechanism(核心贴图，CellEntity 基类)
   ├ MechanismCells / PlayerCells（TileMapLayer，运行时同步占格/身体）
Scenes（窗口级场景，change_scene 全屏切换）
   ├ Scenes/UI/MainMenu.tscn（入口） / LevelSelect.tscn（扫描关卡）
   └ Scenes/Levels/Level_<nn>.tscn
数据
   ├ Resources/Config/Balance.tres（全局数值，@export；无关卡 .tres——布局即场景）
规则与算法（C#，项目内；规则唯一权威）
   ├ Scripts/Algorithms/RuleState.cs       玩法规则唯一实现（trail / 步数 / 机关生长 / 死局）
   ├ Scripts/Algorithms/GridModel.cs       网格数据 + BFS（不依赖 Godot）
   ├ Scripts/Algorithms/MechanicShapes.cs  机关形状 / cover_level
   └ Scripts/Algorithms/Search/            精确 BFS /（后续）FastPlanner / 生成 / 评分
```

**依赖方向：** Autoload ← 关卡 ← 实体 ← 场景。禁止反向依赖：Autoload 不引用具体玩法类；实体不直接调关卡内部（用信号）。

### 1.1 规则与算法层（C#，项目内，单一权威）
- **职责**：玩法规则唯一实现（`RuleState`）、网格模型与 BFS（`GridModel`）、机关形状（`MechanicShapes`）、精确 BFS / 搜索 / route-first 生成 / 双维度评分；纯数据进出（`LevelSpec` / `LevelSolution` / `Score`）。
- **v4 生成管线**：Portfolio 调度（`Generation/GenerationPortfolio.cs`，`hash(seed, level_index)` 按档位选择 structured / noise）、设计公平门（`Model/DesignFairnessGate.cs`，DominanceGap / DecoyProof / GateNecessity）、结构注入（`RouteFirstGenerator.InjectDeadEndForks`，路线旁深度 2 死胡同 + 诱饵花瓣）；来源写入 `LevelSpec.generation_source`，公平门指标写入 `fair_*`。
- **接入**：C# 类（普通类 + `RefCounted`，供 GDScript 持有）→ GDScript `LevelState.gd` 适配层（字段同步 + 转发）→ `Level.gd`；窄 API、粗粒度调用（不逐帧）。
- **权威**：玩法规则以 C# `RuleState` 为唯一实现；GDScript 不再保留规则副本；求解器 / 生成器返回的路线必须经同一 `RuleState` 重放校验。
- **降级**：算法异常/超时时，提示可退回预烘焙路线；生成模式提示不可用，不得崩溃游戏。C# 是游戏程序集的一部分，**游戏本体必须用 .NET/mono 构建**；Web 导出不支持。
- **构建 / 测试**：Godot 根 `.csproj` 单项目构建，无独立类库 / CLI；测试全部在引擎内 headless（`tests/core/` C# 断言场景 + headless 工具；未引入 GUT）。

## 2. Autoload 单例
`ButtonAudio`（`Scenes/UI/ButtonAudio.tscn`，脚本 `Scripts/UI/ButtonAudio.gd`）负责全局按钮点击音效，自动监听场景树新加入的 BaseButton，无需业务脚本调用；始终处理以支持暂停界面，跨场景保留以完整播放余音。


| 单例 | 文件 | 职责 | 对外接口（稳定，勿擅改） |
|------|------|------|--------------------------|
| `GameManager` | `Scripts/Autoload/GameManager.gd` | 顶层状态、场景切换、关卡入口 | `balance` `start_level(path)` `restart_level()` `change_scene()` `back_to_level_select()` `back_to_main_menu()` |
| `EventManager` | `Scripts/Autoload/EventManager.gd` | 全局信号总线（Gameplay 信号见 §3） | 各 `signal`（追加到文件 `## Gameplay` 区块并同步本表） |
| `SaveManager` | `Scripts/Autoload/SaveManager.gd` | 每关最佳步数存档 | `record_result(key, steps)` `best_steps_for(key)` |
| `SfxManager` | `Scenes/Audio/SfxManager.tscn`（脚本 `Scripts/Autoload/SfxManager.gd`） | 全局玩法/AVG 音效：订阅玩法信号自动播放、供打字机逐字调用 | `play_text_blip()`；玩法信号订阅见 §3 |

> 曾存在 ResourceManager / AudioManager 两个 Autoload，因零调用已随 v1.7 精简移除；v1.18 起以职责更聚焦的 `SfxManager`（仅玩法/AVG 音效，见本表）恢复音频接入，落地口径见 [功能需求](../design/功能需求文档.md) §5.5。

Autoload 在 `project.godot` `[autoload]` 段登记；代码直接以类名调用（如 `GameManager.start_level("res://Scenes/Levels/Level_01.tscn")`）。

## 3. 事件总线（Gameplay 信号）

在 `EventManager` 的 `## Gameplay` 区块声明；勿删改仍在 emit 的信号签名（新增需同步本表）：

```gdscript
signal level_loaded(level_id: int)
signal player_moved(head: Vector2i)          # 每次有效移动/截断
signal max_length_changed(new_max: int)       # L 变化
signal move_count_changed(count: int)         # 步数变化
signal food_eaten(pos: Vector2i)
signal mechanism_grew(new_level: int)         # 全体机关 +1 后的阶段
signal input_locked(locked: bool)             # 机关动画期间
signal level_cleared(level_id: int, steps: int)
signal level_failed(level_id: int)
```

> 现状：Level 内 UI 刷新/胜负结算为直接调用（Level→HUD、SaveManager）；信号用于跨系统解耦与扩展预留。已落地订阅方：**SfxManager** 订阅 `player_moved`/`food_eaten`/`mechanism_grew`/`level_cleared`/`level_failed` 播放玩法音效（§2，素材见 [开发文档](../开发文档.md) §3.9 A-11~A-16）。

## 4. 数据

- `Balance.tres`（`Scripts/Data/Balance.gd`，@export）：全局基准数值数据；`GameManager._ready` 加载为 `GameManager.balance`。单关可在 Level 根节点用 `*_override>0` 覆盖 4 项玩法数值（0=沿用全局）。
- 剧情数据：`Resources/Dialogue/Characters.json`（角色注册表）+ `Resources/Dialogue/Story_*.json`（每段剧情一个文件）；JSON 经 `FileAccess` 读取解析，不走引擎资源管线；结构/字段见 [开发文档](../开发文档.md) §4.6。
- 机关形状/像素换算为静态类：`MechanicShapes`（C#）、`GridMetrics`（GDScript）；关卡规则状态为 C# `RuleState`（由 `LevelState.gd` 适配转发）；TileMap 贴图：`Ground` → `TerrainGrassBlob47.tres`（**47-blob 地板**，corners+sides 8 邻接自动贴边；旧关沿用 `TerrainFloor.tres` 16 变体 4 角直到逐关迁移），`Obstacles/MechanismCells` → `TerrainWall/Mech.tres`（**墙/机关花同为 47-blob**：墙 47 列 × 1 行、机关 47 列 × 3 帧行动画行，peering 逐列与地板一致，见 [开发文档](../开发文档.md) §4.4），`PlayerCells` → `PlayerSnek.tres`（纹理 `Art/Tiles/path.png`：管道连接件 + 头/尾格端点半截瓦）；头/尾为独立 Sprite 贴图（头=Algee-all.png 4 方向 × 3 帧精灵表）；实体单贴图在 `Art/Sprites/`（正式 png / spawn.svg 编辑器占位）。
- 关卡没有 LevelDefinition `.tres`：布局 = 关卡场景内的实体节点（§5.3）。
- 规则与算法数据契约（规划/在建）：`LevelSpec` / `LevelSolution` / `Score` JSON，`schema_version` / `generator_version` / `solver_version` / `scoring_version` 独立版本化；生成 RNG 只在 C# 侧实现并版本化。字段与约束见 [正式上线待办](../planning/正式上线待办.md) §2.4。

## 5. 场景编排

### 5.1 入口与切换
`project.godot run/main_scene = Scenes/UI/MainMenu.tscn`。菜单/选关/关卡均为**完整独立场景**，用 `GameManager.change_scene()` 全屏切换（无持久根容器）。

### 5.2 LevelSelect
关卡列表由 `GameManager.list_levels()` 统一提供：扫描 `res://Scenes/Levels` 下 `Level_*.tscn`（自动排除 `LevelTemplate.tscn`），按 `level_id` 排序；LevelSelect 将其渲染为**每关一行按钮 `序号 | 关卡名`**（点击调用 `GameManager.start_level(path)`），胜利面板"下一关"用同一列表调 `GameManager.start_next_level()`。

### 5.3 关卡（场景直编，Level.gd）
- 每关一个场景文件，根节点挂 `Scripts/Systems/Level.gd`；实体子节点决定内容。
- 实体位置语义：导出 `cell: Vector2i`（节点 position = `GridMetrics.cell_center(cell)`）；编辑器拖动自动吸附（@tool，逻辑在 `CellEntity` 基类，Mechanism 继承之）。
- 运行时 `Level._ready`：递归扫描实体 → 计算地图范围（Ground/Obstacles 涂格 + 实体格的外接矩形；**完全空白才退回 map_size**）→ 布玩家 → 同步机关/玩家层 → 开始。
- World/Cam：脚本运行时**不移动、不缩放**；World 默认 (0,0)，Cam 位置由作者在编辑器摆放，编辑器所见即游戏所得。
- 机关：核心=Core 单贴图（`z_index=1` 浮于瓦片层）；逻辑占格由 C# `RuleState` 用 `cover_step`（每格第几次生长被覆盖）+ `shielded`（身体挡格延迟）维护，规则等价于逐机关补占；生长体占格（含核心格）同步到 `MechanismCells` 层确定性贴边。离线可解性/路线用 `tools/LevelSolver.tscn`（headless，调用 C# `ExactBfsSolver`）。
- 渲染：Ground/Obstacles 由作者在 TileMap 涂格；机关生长体/玩家身体由脚本同步到 `MechanismCells`/`PlayerCells` 层；头/尾独立 Sprite 由 `PlayerFx` 承载；实体子节点画自身贴图。
- 胜负/结算：关卡本地面板；通过 `EventManager.level_cleared/failed`（现状直接调用）+ `SaveManager.record_result`。
- 剧情演出：`DialogueOverlay`（CanvasLayer `layer=20`）由 Level 运行时懒实例为子节点（§5.4 的 LevelHUD 是 `layer=10`，剧情层盖其上）；三触发点 `story_start/story_win/story_fail` 见 [开发文档](../开发文档.md) §4.6 与 [功能需求文档](../design/功能需求文档.md) §5.6。

### 5.4 输入锁
机关生长动画期间 `input_locked=true`；`Level._unhandled_input` 忽略移动输入（按键丢弃，不排队）；`restart`(R) 始终可用。Esc 由 LevelHUD 处理，打开场景树内暂停菜单并暂停 SceneTree；继续、重开、退出均先解除暂停。

## 6. 输入
- 动作集中在 `project.godot` `[input]`：`move_up/down/left/right`、`restart`(R)、`ui_*`。
- 代码用 `Input.is_action_pressed("move_up")`，禁裸查键码。

## 7. 说明：本作不使用物理
- 网格解谜基于数据判定（GridSystem），渲染为 TileMap 瓦片/贴图；无需 RigidBody/Area 碰撞。
