# Skill: 玩法设计上下文（game-design-context）

**描述：** 注入本作 2D 网格解谜的设计支柱、术语与阅读路由。涉及走格 / 身长 / 截断 / 机关生长 / 食物 / 胜负 / BFS / 关卡 / HUD / 数值时使用，确保先读功能需求原文再动手。

> 注意：本机全局技能目录可能有同名 `game-design-context`（用于卡牌 / 合成台项目）。**在本仓库工作时以本文件为准**，不要套用其他项目机制。

本技能只做「读哪一份设计原文」的路由与长期原则，**不维护**易变数值、关卡清单、资产状态；一切以 [功能需求文档（权威）](../../design/功能需求文档.md) 为准。

## 使用场景

- 实现或修改走格、截断、身长硬上限、机关生长、食物、胜负、BFS 死局
- 调整玩法数值、`Balance.tres` 或关卡 `*_override`
- 设计 / 评审关卡、HUD、反馈、剧情触发点
- 讨论玩法机制，或发现文档与实现存在歧义

## 设计支柱（长期稳定，已冻结）

1. **尾部钉在起点**：身体 = 从 S 到 head 的连续轨迹，长度硬上限 L；没有“弹出中部格”。
2. **花丛只收紧不放松**：机关随有效步数生长，阶段只增不减；满级后每次周期仍刷新补格。
3. **食物只加身长**：吃花瓣增加 L（增量见功能需求 §7），不改变机关节奏；截断 = 重规划，计 1 步。
4. **胜负清晰**：踏入蓝花（E）= 胜；BFS 无通路，或身长达上限后 E 与所有剩余食物都超出可达范围 = 负。
5. **每一步都是取舍**：扩张可达范围 ↔ 花丛按步数收紧；不引入实时操作、物理碰撞或随机性。
6. **规则冻结**：不擅自增删机制或改数值；规则变更先问人类，确认后同步功能需求文档与 `Balance.tres` / 关卡。

## 术语（代码与文档统一）

| 术语 | 符号 | 含义 |
| ---- | ---- | ---- |
| 主角 | Player | head + 身体轨迹；尾部固定在起点 |
| 起点 / 终点 | S / E | 尾部锚点 / 蓝花 |
| 轨迹 | trail | `[S, …, head]`，连续路径 |
| 最大身长 | L | 轨迹长度上限；初始值与食物增量见功能需求 §7 |
| 有效步 | — | 有效移动 / 截断才计步；无效移动不计 |
| 截断 | — | 踏入自身轨迹某格，撤销其后轨迹，计 1 步 |
| 机关 / 花丛 | Mechanism | 分阶段占据格子；中心恒占 |
| 阶段 | lv | 0–4；形状逐级嵌套（权威表见功能需求 §4.2.1） |
| 生长周期 | N | 每 N 个有效步全体机关生长 1 次；N 默认值与单关覆盖见 §7 |
| 占据格 | mech_cells | 机关实际占据格，与障碍同为不可走 |
| 覆盖时刻表 | cover_step | 每格第几次生长被覆盖（实现术语） |
| 身体挡格 | shielded | 生长时被身体占住、延后占据的格（实现术语） |
| 食物 / 花瓣 | Food | 每格一个；被 head 踏入即 L+2 |
| 障碍 | Obstacle | 静态不可走格；`Obstacles` 层涂格，非实体 |
| 死局 | — | BFS 无通路，或身长达上限后够不到 E / 食物 |

> 新术语先在本表登记再进代码，避免同义不同名。

## 长期原则

- **分层**：规则只在 `LevelState`；`Level.gd` 只做表现同步；`GridSystem` 只管网格数据与 BFS；`LevelSolver` 复用 `LevelState`，不复制规则。
- **数据**：全局数值唯一来源 `Resources/Config/Balance.tres`；单关只允许 Level 根节点 4 个 `*_override`；`grow_anim_sec` 仅全局。
- **关卡**：布局 = 场景直编；可走区 = `Ground` 实际涂格；障碍 = `Obstacles` 涂格；机关 / 食物 / 终点 / 出生点 = 实体节点 `cell`。
- **表现**：UI / 贴图 / 布局在编辑器场景树；身体与机关占格只同步到既有 TileMap 层，不在脚本里另画一套。
- **歧义处理**：功能需求与玩法说明冲突时，以功能需求为准；实现细节不反向写成新规则。
