# 评分训练集与标定规范

> 状态：**规划稿（非权威）**。本文只描述人类评分数据的采集、存储与离线标定，不改变任何玩法规则；锚点数值来自用户主观体感，最终以人工验收为准。
>
> 实现状态（2026-11-25）：`RatingStore`、HUD 评分卡、`Level` 记录接线已落地；0–100 每 10 分一档；headless 验证 JSONL 写入成功。
>
> 实现状态（2026-11-26）：评分记录 `algorithm_features` 开始写入评分 v3 交互特征（`h` / `deception` / `cuts` / `contention` / `l_tight` / `d_interaction` / `fairness_auc` 等），可直接用于离线标定。

## 0. 摘要

目标：用真实游玩评分校准算法分，并逐步优化 V3 的权重、模板先验与评分曲线。

三条原则：

1. **盲评**：评分前不显示算法分、`template_id`、`H`、公平性；
2. **记录地图**：存 `spec_json` + `route`，以后算法改了可以重算特征，但人类标签不变；
3. **分层采样**：模板 / 自由、档位、分数段都要覆盖，不能只收高评分关卡。

**一句话：** 游戏内 0–100 下拉评分 → JSONL 本地记录 → 离线单调校准 + 有序回归 / 排序 → 更新评分与生成权重。

---

## 1. 目标与非目标

| 目标 | 非目标 |
| --- | --- |
| 采集可复现的人类难度标签 | 用少量标签训练神经网络 |
| 校准 `D_interaction → HumanScore` | 用人类分直接改玩法规则 |
| 比较模板 / 自由、不同模板的体感差异 | 让用户手工计算特征 |
| 提供最小训练集与停止条件 | 追求统计上完美的置信区间 |

## 2. 游戏内评分 UI

### 2.1 评分卡

在结算面板或调试浮层（建议 F9 打开）显示：

```
┌──────────────────────────────────────┐
│ 关卡评分（0–100，每 10 分一档）      │
│ [ 70 ▼ ]   [ 确认记录 ]   [ 跳过 ]   │
│ 备注（可选）：______________________ │
└──────────────────────────────────────┘
```

- 下拉：`0,10,20,...,100`（11 档）。若使用 1–10 十档，记录 `human_score_10` 与 `human_score_100 = ×10`。
- **评分前隐藏**：算法分、`template_id`、`generation_mode`、`H`、`fairness`。
- 确认后显示：`已记录：算法 78 / 你的 70 / seed 20261125 / free`。
- 「跳过」也写一条 `human_score=null`，用于统计“不想评”的样本，不参与拟合。
- 可选「不确定」按钮：`human_confidence="low"`，拟合时降权。

### 2.2 评分顺序

1. 进入关卡；不显示任何算法信息；
2. 正常游玩；允许使用提示，但记录 `hint_used`；
3. 结算后打分；
4. 确认写入；
5. 显示算法分与模式，供对照，但不允许修改已确认的标签（避免事后调整偏差）。

### 2.3 防止锚定

- 算法分、模板名、模式名在确认前一律隐藏；
- 不在关卡内 HUD 显示“本关预测难度”；
- 不在评分卡上显示历史平均分。

## 3. 存储

### 3.1 位置

| 环境 | 路径 | 说明 |
| --- | --- | --- |
| 开发期（编辑器 / debug） | `data/ratings/session_<id>.jsonl` | 项目本地，Agent 可读 |
| 导出构建 | `user://ratings/session_<id>.jsonl` | `res://` 导出后只读 |
| 导出按钮 | 用户选择路径 | 把 `user://ratings/` 复制出来 |

- 每行一个 JSON；追加写入；确认时写，不每帧写。
- 文件名带 `session_id`，避免并发损坏。
- 地图用 `spec_json` 存；可选存 320×180 缩略图到 `data/ratings/thumbs/`，不要默认存大图。

### 3.2 Schema

```json
{
  "schema_version": 1,
  "rating_id": "20261125-153012-0001",
  "created_at": "2026-11-25T15:30:12+08:00",
  "session_id": "20261125-A",
  "app_version": "0.1.0",
  "generator_version": 7,
  "scoring_version": 6,
  "calibration_version": 1,
  "generation_mode": "free",
  "requested_mode": "free",
  "template_id": "free",
  "free_field_params": {
    "m": 2,
    "cap": 3,
    "growth_interval": 6,
    "initial_levels": [0, 2],
    "center_distribution": "poisson",
    "obstacle_model": "noise_cluster"
  },
  "novelty": 0.37,
  "seed": 20261125,
  "tier": "hard",
  "spec": { "...LevelSpec..." },
  "route": "DDSS...",
  "steps": 31,
  "target_steps": 30,
  "algorithm_score": 78,
  "algorithm_features": {
    "h": 5,
    "h_is_upper_bound": true,
    "deception": 0.42,
    "cuts": 0.55,
    "contention": 0.31,
    "l_tight": 0.48,
    "fairness_auc": 0.82,
    "fairness_min": 0.71,
    "raw_interaction": 64.2,
    "raw_baseline": 18.4
  },
  "human_score": 70,
  "human_score_10": null,
  "human_scale": "0-100-step-10",
  "human_confidence": "medium",
  "human_notes": "第三个机关太快，路线读不出来",
  "hint_used": false,
  "hint_count": 0,
  "attempts": 3,
  "completed": true,
  "time_sec": 182
}
```

必填字段：

- `schema_version`、`rating_id`、`created_at`、`session_id`
- `generator_version`、`scoring_version`
- `generation_mode`、`template_id`
- `spec`、`route`、`steps`
- `algorithm_score`、`algorithm_features`
- `human_score`（或 `null`）
- `hint_used`、`hint_count`

`generation_mode` 是**实际**模式（`template` / `free` / `fallback` / `route_first`）；V3 生成器落地前可能是 `route_first`。`requested_mode` 是 p_free 策略的请求值（`template` / `free`），用于对比“请求 vs 实际”。

模板模式：

```json
"generation_mode": "template",
"template_id": "T4_multi_gate_counter",
"free_field_params": null
```

降级模式：

```json
"generation_mode": "fallback",
"template_id": "route_first",
"fallback_from": "free",
"fallback_reason": "unsolvable"
```

### 3.3 版本与重算

- `spec_json` + `route` 是地图快照；算法升级后可以用新特征重算，但 `human_score` 不变；
- `algorithm_score` 是**评分当时**的分数，不覆盖；
- 新增 `rescored_v6` / `rescored_v7` 字段时，保留旧字段，便于对比；
- 地图去重：`spec_hash = hash(canonical_json(spec))`；同一张图重复评分时记录 `duplicate_of`。

## 4. 采样策略

### 4.1 覆盖矩阵

必须覆盖：

| 维度 | 取值 |
| --- | --- |
| `generation_mode` | template / free / fallback |
| `template_id` | T0–T8 / free |
| 档位 | easy / normal / hard / expert |
| 人类分数段 | 0–30 / 30–60 / 60–80 / 80–100 |

建议配额（第一轮 80 条）：

```
低分 0–30：20%
中分 30–60：30%
高分 60–80：30%
Expert 80–100：20%
模板 : 自由 ≈ 4 : 1
```

- 每个模板至少 5 条；T0–T2 可以少，T3–T8 至少 10 条；
- 自由模式至少 15–20 条，用于比较模板 / 自由；
- L1–L5 作为固定锚点，每轮首尾各打一次，检测标准漂移。

### 4.2 主动学习

前 60 条之后，不要随机生成，优先补：

- 当前模型预测与人类分残差最大的模板 / 分数段；
- 预测不确定（`H` 接近分档边界、公平性接近阈值）的关卡；
- 训练集中样本最少的 `(template_id, tier, score_band)` 格。

### 4.3 重复样本

- 10% 的关卡隔一段时间重复评分，用于估计标签噪声；
- 同一张图两次分数差 ≥2 档时，标记 `noisy=true`，拟合时降权或剔除。

## 5. 最小训练集

| 目的 | 最小 | 建议 | 说明 |
| --- | --- | --- | --- |
| 单调校准（1 维曲线） | 50 | 100–150 | 覆盖 0–100 全段 |
| 5 个交互权重 | 80–100 | 200–300 | 10–20 条/参数 |
| 9 个模板偏移 | 90（10/模板） | 180–270 | 正则化后可少 |
| 4 个档位边界 | 80（20/档） | 200+ | 每档都要有样本 |
| 模板 vs 自由比较 | 30（15/组） | 80+ | 分组均值 + 置信区间 |
| Spearman ρ=0.4 显著 | ≈45 | 80–100 | 近似 power 0.8 |
| Spearman ρ=0.3 显著 | ≈85 | 120+ | 近似 |
| 神经网络 | 2,000 | 5,000+ | 当前不建议 |

**结论：**

- **最低可用：60–80 条**（覆盖矩阵不能缺格）；
- **稳定校准：150–200 条**；
- **权重 / 模板优化：300–500 条**；
- **神经网络：当前不做**；先用 isotonic + 有序回归。

## 6. 离线标定方法

### 6.1 单调校准

```
HumanScore ~ D_interaction
```

- 用 isotonic regression 得到单调序列；
- 再用 PCHIP 平滑；
- 与 L1–L5 的 5/15/30/40/75 锚点合并；
- 输出新的 `ScoreCalibration` 曲线与 `score_anchors.json`。

### 6.2 权重拟合

```
HumanScore ~ w0 + w1·H_norm + w2·Deception + w3·Cuts
           + w4·Contention + w5·L_tight + template_offset
```

- 有序回归（proportional odds）或成对排序（pairwise ranking）；
- 约束 `w_i ≥ 0`，便于解释；
- 用 70/30 或 leave-one-out 交叉验证；
- 用 bootstrap 估计权重置信区间；只有稳定超出噪声才改。

### 6.3 模板偏移

- `template_offset` 用正则化均值（shrinkage）估计；
- 样本少的模板向全局均值收缩；
- 偏移显著为正：该模板被算法低估；为负：被高估；
- 偏移用于调整生成器的 `TemplatePrior`，不直接改玩法。

### 6.4 残差分析

- 残差 = 人类分 − 校准后算法分；
- 按 `template_id`、`generation_mode`、`H`、`fairness`、`hint_used` 分组；
- 系统性正残差 → 需要新特征 / 新模板；
- 系统性负残差 → 评分项过重或模板先验过强。

### 6.5 评估

- Spearman / Kendall（主）；
- 分档准确率（Easy / Normal / Hard / Expert）；
- 高分段（≥75）的召回率与误报率；
- 模板 / 自由分组的均值差与置信区间。

## 7. 数据质量

| 检查 | 处理 |
| --- | --- |
| 缺失 `human_score` | 保留但不参与拟合 |
| 重复 `spec_hash` | 记录 `duplicate_of`；重复评分用于噪声估计 |
| 评分过快（time_sec 异常小） | 标记 `low_confidence` |
| 使用提示 | `hint_used=true` 单独分组；不与盲评混在一起 |
| 标准漂移 | 每轮重打 L1–L5；按 session 归一化 |
| 版本混杂 | 按 `generator_version` / `scoring_version` 分组；旧图可重算特征 |

## 9. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 只收高分样本 | 低分段曲线失真 | 强制配额 + 主动学习 |
| 看到算法分再打分 | 标签变成复读 | 盲评；确认后显示 |
| 标签噪声 | 权重不稳 | 重复样本、confidence、bootstrap |
| 标准漂移 | 前后不可比 | L1–L5 重打；session 归一化 |
| 使用提示后评分 | 难度体感被改变 | 记录并单独分组 |
| 模板 / 自由混在一起 | 无法判断模板偏差 | 分层统计；`generation_mode` 作为分组变量 |
| 地图未存 | 算法升级后无法重算 | 必须存 `spec` + `route` |
