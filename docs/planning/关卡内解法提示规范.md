# 关卡内解法提示规范（Hint Overlay）

> 状态：**规划稿（非权威）**。本文只描述局内解法提示的表现与交互，不改变任何玩法规则；规则以 [功能需求文档](../design/功能需求文档.md) §4 为准。
>
> 实现状态（2026-11-25）：`HintOverlay.tscn` / `HintOverlay.gd` / `HintRoute.gdshader` / HUD `HintBtn` / `Level` 接线已落地；headless 验证 L1 路线 9 步、10 个点。视觉与手感待人工验收。
>
> 关联：[随机关卡算法 v4 整体改造方案](随机关卡算法v4-整体改造方案.md) · [正式上线待办](正式上线待办.md)

## 0. 摘要

在关卡 HUD 增加「提示」按钮。点击后在地图上绘制一条从起点流向终点的解法路线：

- **动态**：一条亮带沿路线从 S 向 E 流动；
- **变色**：起点暖色 → 终点冷色；
- **透明度热衰减**：起点不透明度高，沿路线逐渐变淡；
- **不改变玩法**：不移动玩家、不消耗资源、不锁输入、不影响胜负判定。

提示路线来源：

- 随机关卡：`GameManager.generated_route`（生成时的规范解）；
- 手编关卡：`LevelState.solve_exact()` 运行时求解一次并缓存（5 个手工关卡成本可接受）；
- 若求解 `UNKNOWN` 或不可解：按钮禁用，不显示错误弹窗。

---

## 1. 目标与非目标

| 目标 | 非目标 |
| --- | --- |
| 让玩家看到一条可通关的规范路线 | 自动移动 / 自动通关 |
| 路线方向、颜色、透明度表达“从 S 流向 E” | 逐步强制提示 / 只能按提示走 |
| 手编关卡与随机关卡都能用 | 修改规则、机关、数值 |
| 提示使用可记录，供评分训练集分析 | 用提示替代玩家思考 |

## 2. 路线数据

### 2.1 随机关卡

`GameManager` 已保存：

```gdscript
GameManager.generated_route  # "A/D/W/S" 方向串
GameManager.generated_spec_json
```

直接使用 `generated_route`；不需要重新求解。若为空，回退到手编求解路径。

### 2.2 手编关卡

`LevelState` 已暴露：

```gdscript
func solve_exact(max_states: int) -> Dictionary
# 返回 {"status": "SOLVABLE|UNSOLVABLE|UNKNOWN", "route": "...", "steps": N, "states": N}
```

流程：

1. 首次点击提示时调用 `state.solve_exact(1_200_000)`；
2. `SOLVABLE`：缓存 `route`，显示；
3. `UNSOLVABLE`：按钮禁用；
4. `UNKNOWN`：再尝试一次 `4_000_000`；仍 `UNKNOWN` 则禁用并记录 `hint_unavailable`。

结果缓存在 `Level` 实例内，重开同一关不必重复求解。

### 2.3 方向串 → 路线格

```
起点 = state.spawn_cell（或 route 起点）
逐字符 A/D/W/S 推进，得到 cell 序列
世界坐标 = GridMetrics.cell_center(cell)   # CELL_PX = 32
```

### 2.4 玩家已移动时

- 若 `head` 在路线格中：从 `head` 的位置开始画剩余段（热衰减从当前头部开始），已走过部分隐藏或极淡；
- 若 `head` 不在路线格中：画完整 S→E 路线，并在 HUD 上提示“当前不在提示路线上”；
- 不重新求解当前状态（第一版）；后续可加“从当前状态重解”。

## 3. 视觉规范

### 3.1 组成

提示由**预置场景** `HintOverlay.tscn` 实现，不在脚本里 `_draw`、不 `new` 控件：

```
HintOverlay (Node2D)
├─ Outline (Line2D)      # 深色描边，宽 10 px，alpha 0.25
└─ Route (Line2D)        # 主路线，宽 6 px，Gradient + ShaderMaterial
```

- `Route` 使用 `GradientTexture1D` + `texture_mode = TEXTURE_MODE_STRETCH`，使 `UV.x` 沿路线 0→1；
- `ShaderMaterial` 参数：

```text
hot_color      = #FFD166   # 起点暖色
mid_color      = #FF8A5C   # 中段过渡
cool_color     = #5AD1C8   # 终点冷色
alpha_start    = 0.95
alpha_end      = 0.25
flow_speed     = 0.55      # 路线/秒
band_width     = 0.16      # 亮带宽度（UV 比例）
trail_length   = 0.35      # 亮带尾部衰减长度
```

### 3.2 热衰减

- 基础渐变：`t = UV.x`，颜色 `hot → mid → cool`，透明度 `mix(alpha_start, alpha_end, t)`；
- 含义：起点“热”（明显），终点“冷”（淡出），形成从 S 流向 E 的视觉方向；
- 不在中途突然变色；三段渐变用平滑插值。

### 3.3 流动亮带

```glsl
float flow = fract(UV.x - TIME * flow_speed);
float band = smoothstep(0.0, band_width, flow)
           * smoothstep(0.0, band_width, 1.0 - flow);
float trail = smoothstep(0.0, trail_length, flow);
vec3 color = mix(base_color, hot_color, band * 0.55);
float alpha = base_alpha + band * 0.25;
```

- 亮带循环从 S 向 E 移动；
- 亮带经过处短暂提亮，尾部自然衰减；
- 不使用高亮泛光 / 模糊，避免遮挡地块与机关。

### 3.4 层级与可见性

- 插入到 `World` 下，位于 `Ground` / `Obstacles` / `MechanismCells` 之上、`PlayerCells` / `PlayerFx` 之下；
- 若使用 CanvasLayer，层号必须低于 HUD；
- 不覆盖 HUD、结算面板、剧情覆盖层。

### 3.5 开关

- HUD「提示」按钮：`提示` ↔ `隐藏提示`；
- 显示时淡入 0.15 s，隐藏时淡出 0.12 s；
- 不自动消失；玩家手动关闭；
- 重开 / 胜负 / 切场景时自动隐藏。

## 4. 交互与 HUD

### 4.1 按钮

在 `LevelHUD.tscn` 的 `Root/TopArea/ActionsPanel/Actions` 下新增：

```
Actions
├─ RestartBtn
├─ BackBtn
└─ HintBtn      # 新增，文本「提示」
```

`LevelHUD.gd`：

```gdscript
signal hint_toggled
func set_hint_available(value: bool) -> void
func set_hint_active(value: bool) -> void   # 切换「提示 / 隐藏提示」
```

`Level.gd`：

```gdscript
func toggle_hint() -> void
func _route_for_hint() -> String
```

### 4.2 可用性

- 路线为空 / `UNSOLVABLE` / `UNKNOWN`：按钮禁用，tooltip「本关暂无提示」；
- 剧情播放期间：禁用，避免覆盖剧情层；
- 生长动画 / 输入锁期间：允许开关（纯视觉，不抢输入）；
- 胜负结算后：隐藏并禁用。

### 4.3 快捷键（可选）

- 新增 InputMap action `hint`，默认 `H`；
- 与按钮等价；若不想改 InputMap，第一版只做按钮。

### 4.4 记录

- `Level` 记录 `hint_used_count`、`hint_first_step`；
- 写入评分记录：`hint_used: true/false`、`hint_count`；
- 训练集分析时，**使用过提示的评分单独分组**，避免“看过答案再打难度分”的偏差。

## 5. 生命周期

| 时机 | 行为 |
| --- | --- |
| 首次点击 | 懒加载路线（手编求解 / 随机读取）；显示 |
| 再次点击 | 隐藏 |
| 玩家移动 | 若 head 在路线上，重建剩余段；否则保持完整路线 |
| 重开本关 | 隐藏；路线缓存可复用（同 spec） |
| 胜利 / 失败 | 隐藏；按钮禁用 |
| 切场景 | 释放 overlay；清缓存 |
| 剧情开始 / 结束 | 禁用 / 恢复按钮 |

## 7. 复杂度与性能

| 项 | 复杂度 | 说明 |
| --- | --- | --- |
| 方向串 → 格序列 | `O(route length)` | ≤ ~40 |
| 设置 Line2D 点 | `O(N)` | 一次性 |
| 流动动画 | GPU 像素级 | 无每帧 CPU 分配 |
| 手编求解 | `O(4·3^{L−1}·2^F)` | 每关一次，缓存 |
| 随机读取 | `O(1)` | 直接读 `generated_route` |

- 不在 `_process` 中重建点集；只在显示 / 玩家移动 / head 变化时重建；
- 不求每帧重新求解；
- 目标 1920×1080（World 1.5× 放大）、zoom 1.5、CELL_PX 32 下路线宽度 6 px 可读。

## 10. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 玩家已移动后路线不匹配 | 提示误导 | head 在路线上时只画剩余段；否则提示“当前不在路线上” |
| 手编关卡求解 `UNKNOWN` | 无提示 | 加大预算一次；仍失败则禁用并记录 |
| 路线遮挡机关/地块 | 可读性差 | 半透明、描边、层级在玩家之下 |
| 提示被当成“自动通关” | 体验变差 | 纯视觉、不移动玩家；可选记录使用次数 |
| shader 在 d3d12 下差异 | 显示异常 | 用标准 CanvasItem shader；在 Forward+ d3d12 下验收 |
| 评分被提示污染 | 训练集偏差 | 记录 `hint_used`，单独分组 |
