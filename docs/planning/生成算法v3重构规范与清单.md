## 0. 摘要与已确认决策

**一句话：** 把当前“先生成路线、再放机关且机关避开路线”的 route-first，改成“时间展开 + 时空割 + 公平性约束 + R2 精确验证”的 interaction-first 生成。

已确认（2026-11-25）：

| 决策 | 结论 |
| --- | --- |
| 机关是否可以压规范路线 | **接受**。机关可以封路、可以迫使玩家绕行/抢时间；这是新算法的主要难度来源 |
| 公平性约束 | **采用模糊化/扩散处理**：对机关占格/等级矩阵做图扩散，得到“感知危险场”，再用 AUC 与模糊隶属度判定公平性 |
| 评分锚点 | L1–L5 暂用主观总分 **5 / 15 / 30 / 40 / 75** 作为定性锚点；拟合单调曲线后，生成关卡只使用拟合函数输出 |

**不在本文范围内：** 规则改动、数值改动、剧情 / 美术 / 音频、关卡场景直编、Web 导出、外部插件 / NuGet / 神经网络运行时。

## 1. 背景与问题定义

### 1.1 当前生成器的结构性约束

当前 `RouteFirstGenerator` 的流程是：

1. 生成地形与障碍；
2. 选出生点 / 终点；
3. BFS 出一条规范路线；
4. 在路线之外放机关，并用时间窗验证“机关覆盖路线格的时刻晚于玩家经过”；
5. 精确求解、重放验证、评分。

对应代码：

- [PlaceMechanisms](../../Scripts/Algorithms/Generation/RouteFirstGenerator.cs) 只从“未走过、离路线 ≤2”的格子选中心；
- `ValidateMechanismWindows` 要求 `coverStep(c) × I ≥ 玩家经过 c 的步序`；
- 封路核心在行走前放置，行走器会绕开它。

**等价约束：** 规范路线是一条静态路径；机关只影响玩家身后的格，不参与“玩家下一步该往哪走”的决策。

### 1.2 后果

- 所有随机关卡都退化为“静态最短路 + 绕行”，身体与机关没有竞争；
- 评分测到的是路线长度、绕行、机关邻近度，而不是交互；
- 分数虚高：20×20、30 步、机关贴着路线但从不封路的图，也能拿到接近 100 的分数，体感却接近 L3。

### 1.3 目标与非目标

| 目标 | 非目标 |
| --- | --- |
| 生成“机关会真实改变决策”的关卡 | 修改移动 / 生长 / 胜负规则 |
| 每个接受关卡都有 R2 精确可赢证明 | 用神经网络替代可解释算法 |
| 公平性可计算（感知危险场可预测真实危险） | 引入外部依赖或运行时训练 |
| 用复杂度而非毫秒衡量算法 | 以墙钟时间作为验收指标 |
| 失败时降级到 RouteFirst，绝不崩溃 | 保证 NP-hard 合成问题的最优解 |

## 2. 形式化模型

### 2.1 关卡与状态

```
Λ = (G, O, S, E, C, a, I, L0, ΔL, F)
G = (V, E)     4 邻接网格
O ⊂ V          障碍
S, E ∈ V       出生点 / 终点
C = {c_i}      机关中心
a = {a_i}      机关初始阶段
I              生长周期
L0             初始最大身长
ΔL             吃花增量
F ⊂ V          食物
```

精确状态：

```
σ = (τ, φ, g)
τ = 从 S 到 head 的简单路径（trail）
φ = 已吃食物集合
g = 生长次数
L(σ) = L0 + ΔL·|φ|
```

转移（与 [RuleState.cs](../../Scripts/Algorithms/RuleState.cs) 一致）：

| 动作 | 条件 | 结果 |
| --- | --- | --- |
| 截断 | `next ∈ τ` 且与 head 相邻 | `τ` 截到 next，步数 +1 |
| 前进 | `next` 在地板、非障碍、非机关占格、`|τ| < L` | `τ` 追加 next；吃花则 `L += ΔL` |
| 生长 | 步数 `% I == 0`，在移动之后 | `g += 1`（封顶）；机关尝试占格；占据 `τ` 的格跳过（屏蔽） |
| 死亡 | 移动/生长后不满足规则 | 无赢路或身长达不到 |

**关键时序：** `StepCore` 是“先移动、后生长、再胜负/死局”。因此第 `t` 步的移动合法性使用第 `t−1` 步生长后的机关集合 `M(t−1)`，而不是 `M(t)`。

### 2.2 机关时刻表

```
g(t) = min(⌊t / I⌋, g_max)
g_max = max_i (cap − a_i)
ℓ_i(t) = min(a_i + g(t), cap)
coverStep(c) = max(0, coverLevel(c − c_i) − a_i)
M(t) = ∪_i S_i(ℓ_i(t)) \ Shield(t)
```

- `coverLevel` 见 [MechanicShapes.cs](../../Scripts/Algorithms/MechanicShapes.cs)：八边形，`max(2·曼哈顿−2, 2·切比雪夫−1)`，上限 4。
- `Shield(t)` 是当前 trail 中会被覆盖的格；生长时跳过，后续生长再补占。
- 机关生长单调：格只会被加入，不会被移除；屏蔽只会延迟占格。

### 2.3 三层判定

| 层 | 状态 | 含义 | 复杂度 |
| --- | --- | --- | --- |
| **R0** | `(v, t)` | 只看地形 / 障碍 / 机关，忽略身长与身体 | `O(V·T)` |
| **R1** | `(v, t, k)` | 加入身长资源：`dist_{G\O}(S, v) ≤ L0 + ΔL·k − 1` | `O(F·V·T)` |
| **R2** | `(τ, φ, g)` | 精确规则：真实轨迹、截断、屏蔽 | `O(4·3^{L−1}·2^F·g_max)`，FPT in `L, F` |

关系：

```
R2 ⊆ R1 ⊆ R0
```

- `R1` 是必要条件的松弛：任何真实可达的 head 都满足 `dist_{G\O}(S, head) ≤ |τ|−1 ≤ L−1`；
- `R1` 不考虑轨迹几何、截断释放长度、身体屏蔽的精确效果，因此可能包含 `R2` 不可达的状态；
- `Δ = R1 \ R2` 是**欺骗空间**：看起来可达、实际不可赢。生成目标是 `max |Δ|`，且 `R2 ≠ ∅`。

### 2.4 复杂度与硬度

| 问题 | 算法 | 复杂度 | 说明 |
| --- | --- | --- | --- |
| R0 可达 / 可行核 | 时间展开 BFS / 后向 DP | `O(V·T)` | 多项式 |
| R1 可达 / `Latest` / `slack` | 分层 BFS / 后向 DP | `O(F·V·T)` | 多项式；`F ≤ 8` |
| R2 精确可赢判定 | 轨迹状态搜索 | `O(4·3^{L−1}·2^F·g_max)` | FPT in `L, F`；`L` 通常 ≤ 15 |
| 最小前瞻 `H` | 迭代加深精确搜索 | `O(T·4^H)` / 策略 | `H` 是难度参数 |
| 机关布置（合成） | 束搜索 + R2 验证 | `O(m·B·|C|·(F·V·T + 3^L·2^F))` | `m ≤ 3`，`B` 束宽，`|C| ≤ V` |
| 合成问题本身 | — | **NP-hard** | 退化情形包含节点型最短路径阻断（SPNI） |

**硬度证明草图：** 固定地形、S/E、`I > T`（不生长）、`L` 足够大、无食物，选择 `m` 个机关中心等价于选择 `m` 个障碍格，使最短 S–E 路径 ≥ `d`。这是节点型最短路径阻断问题，NP-hard（即使限制在二端串并联图）。因此带目标步数/目标难度的生成问题包含 SPNI，是 NP-hard。

**边界提醒：** 若去掉 `L` 上界且不允许截断，这类 Snake 式运动规划在网格图上是 PSPACE-complete。本作允许截断且有 `L` 上界，精确判定是 FPT；`L` 既是玩法资源，也是可判定性的参数。

## 3. 规范

### 3.1 模块与接口

| 模块 | 职责 | 必须不做什么 |
| --- | --- | --- |
| `TimeExpandedModel` | 生成 `M(t)`、`coverStep`、`Latest`、`slack`、`ViableKernel` | 不访问节点 / 场景 / 信号 |
| `CoverageCone` | 单个中心 + 初始阶段的覆盖锥 `{(v,t)}` | 不直接改 `LevelSpec` |
| `PerceivedDangerField` | 图扩散 + 时间软化，输出 `P(v,t)` | 不穿墙扩散；不引入随机 |
| `FairnessEvaluator` | `AUC`、`μ_fair`、硬/软约束 | 不参与规则判定 |
| `InteractionPlanner` | 束搜索机关 / 初始等级 / 食物，目标函数 | 不复制规则；R2 验证必须走 `RuleState` |
| `GenerationJob` | 状态机驱动、候选循环、预算、降级 | 不硬编码关卡布局 |
| `ScoreCalibration` | PCHIP / isotonic 拟合与查表 | 不在运行时训练 |
| `GenerationService` | 缓存、分帧、JSON | 不改变 `RuleState` |

**候选数据结构（C# 契约，snake_case JSON）：**

```text
Candidate {
  spec_json, route, steps, target_steps, target_delta,
  h, deception, cuts, contention, l_tight,
  fairness_auc, fairness_min, perceived_version,
  r1_cells, exact_states, beam_width, attempts,
  success, reason
}
```

**必须保持：**
- 规则唯一实现仍在 `RuleState`；生成器只调用，不复制。
- 所有随机来自 `DeterministicRng`（xorshift64*）；同一 `seed + tier + generator_version` 输出一致。
- 不依赖 `Dictionary` 迭代顺序；所有需要顺序的集合显式排序。
- 浮点扩散固定迭代次数与顺序；跨平台一致性以同运行时为准，测试用 epsilon。

### 3.2 管线阶段

#### P0 地形与障碍（保留）

- 输入：`seed`、`tier`、尺寸阶梯、障碍模型。
- 输出：`Floor`、`Obstacles`、`Width/Height`。
- 不变式：地板最大连通分量 ≥ `targetSteps + 8 + width`；障碍后剩余可走格 ≥ `targetSteps / 0.85`。
- 失败：`地形连通分量过小` → 下一 attempt。

#### P1 建 R1 表

- 输入：地形、障碍、候选 S/E、`L0`、`ΔL`、`F`、机关时刻表（此时可为空）。
- 输出：
  - `coverStep: Cell → int`；
  - `M(t)` 每个生长阶段的机关集合；
  - `Latest(v, k)`：从 `(v, t, k)` 仍能到 E 的最晚 `t`；
  - `slack(v, t, k) = Latest(v, k) − t`；
  - `ViableKernel = {(v, t, k) : slack ≥ 0}`。
- 算法：按 `k = 0..F` 分层；每层在 `G_t` 上做后向 DP。边条件使用 `M(t−1)`。
- 复杂度：`O(F·V·T)`。
- 失败：`ViableKernel` 为空 → 换 S/E 或换 seed。

#### P2 选 S/E 与见证路线

- 目标：找到满足以下条件的 `(S, E, π)`：
  1. `π` 在 R1 中可行，长度落在目标带；
  2. 存在至少 2 条“静态看起来更短”的候选分支；
  3. 走廊的最小割 / 顶点不相交路径数足够小，使 1–3 个机关能形成时空割；
  4. `slack` 在路线中后段出现明显下降。
- 算法：在 R1 表上枚举候选 S/E（外围格 × 距离带），对每个候选计算走廊指标；用目标函数打分，保留 Top-K。
- 复杂度：`O(|S_candidates|·F·V·T)`。
- 失败：无候选 → 换尺寸 / 换障碍模型 / 下一 attempt。

#### P3 时空割搜索（机关）

- 候选中心 `c` 与初始阶段 `a ∈ [0, cap]`。
- 覆盖锥：`Cone(c, a) = {(v, t) : coverStep(c, v) ≤ g(t)}`。
- 交互增益（初值）：

```text
gain(c, a) =
    2.0 × 被 Cone(c,a) 切断的 R1 可行分支数
  + 1.5 × 规范路线 slack 的下降量（归一化）
  + 1.0 × 新增欺骗决策数
  - 1.0 × 使路线变为不可赢的惩罚（R2 不可解直接淘汰）
```

- 搜索：束搜索，节点 = 部分机关集合；每层枚举 Top-`K` 候选中心；用 R1 快速评估，只对束顶做 R2 精确验证。
- 约束：
  - `1 ≤ |C| ≤ 3`；
  - 中心不能与 S/E 重合；
  - 机关初始阶段允许不同，制造先后满级；
  - 允许中心压规范路线；允许机关封死静态最短路。
- 复杂度：`O(m·B·K·(F·V·T + 3^L·2^F))`。
- 失败：束耗尽 → 下一候选 / 降级。

#### P4 公平性校验

- 输入：当前候选的机关集合、`M(t)`、`ViableKernel`、规范路线。
- 感知危险场：

```text
f^(0)(v) = 1 if v ∈ M(t) else 0    （或 level/cap）
f^(k+1)(v) = (1−η)·f^(k)(v) + η·mean_{u~v} f^(k)(u)
P(v,t) = clamp(w_s·f^(K)(v) + w_t·μ_cover(v,t))
```

- 图扩散只在可走图上进行；障碍 / 墙为 Neumann 边界，禁止穿墙。
- 公平性：
  - 对规范路线上每个决策点的合法分支，计算 `unsafe(b)`（R1/R2）与 `P_b`；
  - `AUC`：用 `P_b` 预测 `unsafe(b)`；
  - `μ_fair(b) = smoothstep((P_b − P_safe + δ)/δ)`；
  - 硬约束：`AUC ≥ θ_A` 且所有“有吸引力”的 unsafe 分支 `μ_fair ≥ θ_F`。
- 初值：`σ = 2–3` 格，`θ_A = 0.75–0.8`，`θ_F = 0.6`；需人工验收后调整。
- 失败：不公平 → 回到 P3 取下一束节点；连续失败 → 下一候选。

#### P5 食物与诱饵

- 食物：
  - 放在 `L` 前沿：路线第一次出现 `dist_{G\O}(S, v) = L−1` 的位置；
  - 或作为“时间钥匙”：只在某个生长事件前可吃，吃了才能进入下一段；
  - 数量遵守权威数值（2–6 建议）与目标步数。
- 诱饵：
  - 放在 `R1 \ R2` 的陷阱格：松弛可达但无赢路；
  - 优先“静态看起来更短”（`ds + dg ≤ steps − 2`）且不在规范路线上；
  - 数量按档位（hard/expert 至少 1）。
- 不变式：食物不被机关永久覆盖；关键食物在可吃时间窗内。
- 复杂度：`O(F·V·T)`。
- 失败：无法放置 → 允许 0 食物（低难度样本），但不得破坏可赢性。

#### P6 精确验证、评分、存档

- `ExactBfsSolver` 必须返回 `SOLVABLE`；`ReplayVerify` 必须全程 accepted、无死锁、终点正确。
- 评分调用 [评分算法 v3](评分算法v3重构规范与清单.md) 的 `Score(...)`；分数由拟合函数输出，不使用 5/15/30/40/75 原始定义值。
- 候选进入 MAP-Elites；选格按 `|H − H_target|`、`|steps − target|`、公平性、多样性排序。
- 失败：回到 P3 / 下一候选；全部失败 → P7。

#### P7 降级

- 调用现有 `RouteFirstGenerator` 作为基线；若成功，按新评分输出并标记 `fallback=true`。
- 若仍失败，返回 `success=false` 与原因；不得崩溃、不得死循环。
- 降级结果必须仍通过 `RuleState` 重放；不得放宽规则。

### 3.3 目标函数

```text
maximize  J = 0.40·H_norm
           + 0.20·Deception
           + 0.15·Cuts
           + 0.15·Contention
           + 0.10·L_tight

subject to
  ExactSolve(Λ) = SOLVABLE
  |Steps(Λ) − targetSteps| ≤ tolerance
  FairnessAUC ≥ θ_A
  μ_fair(b) ≥ θ_F   for all attractive unsafe branches
  |C| ≤ 3
  Deterministic(seed, tier, version)
```

- `H_norm = min(H, 8) / 8`。
- 权重为初值，必须按 L1–L5 与批量生成结果校准。
- 硬约束优先于目标值；任何公平性或可赢性失败直接淘汰。

### 3.4 复杂度预算（替代毫秒 / 工作单元）

| 预算项 | 含义 | 初值 |
| --- | --- | --- |
| `MaxR1Cells` | `F·V·T` 表格单元数 | 按尺寸分档 |
| `MaxExactStates` | R2 搜索状态数 | 1.2M（沿用） |
| `MaxBeamWidth` | 束宽 `B` | 4–8 |
| `MaxLookahead` | `H` 上限 | 8 |
| `MaxCenters` | 机关数 | 3 |

- 墙钟毫秒只保留为运行时安全阀，触发时标记 `budget_aborted`，不作为算法质量指标。
- 设计/验收文档中只写 `O(...)`、参数化复杂度、状态数，不写“必须在 X ms 内”。

## 4. 清单

### 4.1 实现清单

#### 模型与数据结构

- [ ] `TimeExpandedModel`：`BuildCoverStep`、`BuildMechSets`、`BuildLatest`、`BuildSlack`、`BuildViableKernel`
- [ ] `CoverageCone`：按中心 / 初始阶段生成覆盖锥；支持多机关并集
- [ ] `PerceivedDangerField`：图扩散（Neumann 边界）、时间软化、归一化
- [ ] `FairnessEvaluator`：分支枚举、`unsafe` 判定、AUC、`μ_fair`
- [ ] `Candidate` / `GenerationResult` 扩展字段与 JSON 序列化
- [ ] `GenerationRequest` 增加 `H_target`、`fairness_theta`、`beam_width`

#### 生成管线

- [ ] P0 保留 `BuildTerrain` / `ObstacleModels`，加不变式断言
- [ ] P1 在候选 S/E 上建 R1 表；失败可换候选
- [ ] P2 走廊选择：目标长度、分支数、最小割、slack 下降
- [ ] P3 时空割束搜索：中心 + 初始阶段；允许压路线；R1 评估 + R2 验证
- [ ] P4 公平性：扩散 + AUC + 模糊隶属；硬约束接入束搜索
- [ ] P5 食物 / 诱饵：L 前沿、时间钥匙、`R1 \ R2` 陷阱格

## 5. 风险与待确认

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| R1 松弛过松 | 大量“看起来可行”实际不可行，搜索被误导 | 用 R2 验证；统计 `Δ` 与真实失败率；必要时收紧球约束 |
| R1 松弛过紧 | 漏掉合法交互路线 | 保留 R2 兜底；允许 `R1` 之外的手工候选 |
| 公平性扩散尺度不当 | 太小事后诸葛，太大全图危险 | σ 取 2–3 格；多尺度回测 AUC |
| NP-hard 束搜索质量 | 高难度关卡生成率低 | 增大束宽 / 换候选；保留 RouteFirst 降级 |
| 浮点扩散跨平台差异 | 确定性测试不稳定 | 固定迭代 / 顺序；测试用 epsilon；必要时定点化 |
| 规则口径变化 | 模型失效 | 以功能需求 §4 为准；规则变更先停下来问人类 |

**待确认：**

1. `θ_A`、`θ_F`、`H` 分档与目标分布，需人工试玩后定稿。
2. 是否允许“机关中心直接压在规范路线上”（当前决策为允许；需在关卡验收中确认可读性）。
3. 扩散尺度是否与镜头 / UI 可见范围一致；需要一次实际观感校准。
