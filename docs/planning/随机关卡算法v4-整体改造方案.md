## 0. 摘要

把当前“**随机地形 + 事后放置**”改成“**双引擎生成 + 统一合同/验证/评分/选关**”：

- **结构图引擎**：先设计谜题结构，再嵌入地形，保证 hard/expert 稳定出高难结构；
- **噪波负型引擎**：岛为障碍、缝隙为通路，负责探索结构图没覆盖的谜题类型；
- 两个引擎输出同一种 `LevelSpec + Certificate`，共用同一套验证、评分、选关；
- 评分从“关卡长什么样”改为“**可行状态漏斗有多紧**”：纯路线结构（回头、环路取食、返回截断、时机卡死）和机关结构一样，都是一等难度来源；
- 公平性从“玩家能不能感知”改为“**设计有没有被绕过**”：地图、机关等级、生长计时全公开，只查支配捷径、诱饵必败、机关必要；
- 节点不是预先拍脑袋定的，而是通过**抽象细化**产生：节点 = 让规范解可实现的最小状态划分，细化次数/半径/信息要求就是难度。

**一句话：** 结构图负责“稳定出高难”，噪波负型负责“发现新类型”，统一验证负责“不破坏公平与可解”，统一评分负责“按决策紧度而不是长度排序”。

## 2. 背景与问题

### 2.1 当前生成器

- 地形由噪波 / CA 生成，岔路是“碰巧出现”的；
- 放置阶段（机关、食物、S/E、诱饵）只能在地图既有特征上做局部选择；
- 地形与放置分开优化会互相拆台：地形太开放 → 机关挡不住；机关太强 → 地形没有足够分支；
- 硬模板命中率偏低，自由模式质量不稳定；
- 难度是“生成后算出来的副产品”，不是“生成时保证的约束”。

### 2.2 当前评分与验证

- 生产分仍以路线 / 枝干混合为主，交互分只做诊断；
- `mech_pressure`（距机关距离）与 `forkSteps`（≥2 可走方向）测的是“长什么样”，不是“玩家要做什么”；
- `H` 是近似上界；公平性主要看感知危险场 AUC；
- 旧的“删机关基线扣除”会把 L1–L3 的交互扣成 0，且会误杀纯路线高难关卡。

### 2.3 改造目标

1. hard/expert 稳定产出高难结构，而不是碰运气；
2. 保留 easy/normal/free 的多样性；
3. 评分与体感一致：纯路线、机关、混合三种难度都能正确排序；
4. 公平性可验证：不存在“明显更优的绕过路线”；
5. 复杂度可控：精确求解只做 Top-K 证书，生成/评分用宏层抽象；
6. 全部可复现：同 seed 同关卡、同证书、同分数。

## 3. 设计原则

1. **双引擎**：结构图保证高难，噪波负型探索新类型，共用验证/评分/选关。
2. **意图先行**：先有谜题结构，再有地形；地形是谜题的实现，不是随机底图。
3. **难度 = 决策紧度**：难度来自可行状态集合被收窄，不来自步数或尺寸。
4. **纯路线是一等来源**：回头、环路取食、返回截断、时机卡死与机关结构同等计分。
5. **公平 = 设计公平**：信息全公开，只查“设计有没有被绕过”。
6. **状态必须完整**：节点状态包含 `(t, L, foodMask, g, phase, tailSummary)`；顺序压进状态，不假设顺序无关。
7. **流量模型只做先验**：黏菌/势场用于吸引力权重，不用于可行性判定。
8. **抽象细化定节点**：节点由“让规范解可实现”的细化过程产生；半径/细化次数/信息要求 = 难度。
9. **目标带而非最大化**：难度峰值在约束临界区；过紧会变成不可解或被迫走廊。
10. **确定性优先**：整数噪波、固定顺序、固定 seed；同 seed 同关卡。
11. **精确求解器做证书**：Top-K 验证，不替代生成；算法失败必须可降级，不得崩溃游戏。

## 4. 总体架构

```text
                    ┌─ 结构图引擎（pattern graph → embed）
Seed / Tier ──→ 调度 ┤
                    └─ 噪波负型引擎（island → skeleton → inject）
                              ↓
                 共享合同 / 验证门 / 评分 / MAP-Elites
                              ↓
                   LevelSpec + Certificate + ScoreVector
```

### 4.1 调度比例（初值，待校准）

| 档位 | 结构图 | 噪波负型 | 目的 |
| --- | --- | --- | --- |
| easy | 20% | 80% | 多样性、教学 |
| normal | 40% | 60% | 混合 |
| hard | 60% | 40% | 稳定高难 + 少量探索 |
| expert | 80% | 20% | 结构保证 + 探索通道 |

调度用 `hash(seed, level_index) % 100`，保持确定性。`generation_source = structured | noise | hybrid` 写入 `LevelSpec`，供统计与 MAP-Elites 使用。

### 4.2 共享产物

| 产物 | 内容 |
| --- | --- |
| `LevelSpec` | 地形、S/E、机关、食物、诱饵、参数、来源、模式标签 |
| `Certificate` | 可解、规范解、诱饵证明、闸门必要性、支配差距、长度预算、时机、骨架同构、确定性 |
| `ScoreVector` | 路线经济分、决策分、节点指标、诊断字段 |

生成器不直接写分数；验证器与评分器是唯一权威。

## 5. 双引擎

### 5.1 结构图引擎（保证高难）

#### 5.1.1 模式库

模式是图上的可组合片段，不是硬编码模板。首批模式：

| 模式 | 对应 | 结构 | 关键参数 |
| --- | --- | --- | --- |
| `StaticBlockedFork` | L3 | 静态更短、被墙/死路封住的分支 | 分支长度、封堵深度 |
| `DynamicFalseFork` | L5 | 静态更短、机关在玩家进入后封住瓶颈 | 闸门位置、初始阶段、生长间隔 |
| `ForcedReturnDeadEnd` | L3 | 死路 + 必经食物 + 踩身体返回 | 入口长 `a`、死路深 `d`、花瓣 `G`、身长 `L` |
| `FarForkFoodReturn` | L3/L5 | 近岔路走不出，远岔路有食物，必须回来截断 | 环长 `C`、入口长 `a`、食物 `G` |
| `TimedLoopTruncation` | L5 | 环路 + 生长相位卡顺序 | `I`、相位、环长 `C`、身长 `L` |
| `OrderedFoodChain` | 通用 | 多个食物必须按序吃，否则长度/时机不够 | 食物顺序、`G`、`I` |
| `ChokepointGate` | L4/L5 | 单闸门卡在 1–2 格瓶颈 | 瓶颈宽度、初始阶段 |
| `StaggeredGates` | L5+ | 错峰多闸门，先后满级 | 各机关初始阶段、间距 |
| `ResourceChain` | 通用 | 必经花瓣链 + 真/假食物 | 食物位置、真假标签 |

#### 5.1.2 图生成与嵌入

1. 用模式文法组合出 `IntentGraph`：`Start → Segment* → Goal`；
2. 节点放房间/区域，边用 A* 铺正交走廊，宽度 1–2 格；
3. 加分离约束：非连通走廊之间间距 ≥2 格，防止意外捷径；
4. 放置 S/E、机关、食物、诱饵；
5. 产出规范解 `π*` 作为证书；
6. 进入共享验证门。

#### 5.1.3 构造式保证

- 连通、无意外捷径、闸门可见；
- 强制截断满足 `单入口 + 必经食物 + a + C ≤ L`；
- 闸门满足 `t_f < t_cover(c) ≤ t_c`；
- 真假食物满足“真：吃完有赢路；假：吃完无赢路且返回被封”。

### 5.2 噪波负型引擎（探索多样性）

```text
fBm / Worley 岛场
  → 阈值 + 形态学（膨胀/腐蚀）
  → 可行走 = 非岛；最大 4-连通分量
  → 距离变换 / 宽度场
  → 骨架化 → 通道图
  → 剪枝：去短支路、合并度 2、统计环路
  → 检测 fork / dead-end / loop
  → 缺失模式注入
  → 共享验证
```

已敲定的约束：

- 岛占比约 0.30–0.45；必须做最大 4-连通分量检查；低于渗流阈值，避免通路断裂；
- 4 邻接移动，避免对角夹点；用膨胀/闭运算封掉对角假通路；
- 通道宽度由距离变换控制；宽度局部极小 = 瓶颈候选；
- 环路太多要裁剪，只保留 1–2 个有设计意图的环；
- 噪声用整数哈希/固定实现，保证跨平台确定性。

**Novelty mining**：通过合同的噪声关卡被 tagger 标记，离线晋升为新的模式，回填结构图库。

### 5.3 融合方式

| 方式 | 做法 | 适用 |
| --- | --- | --- |
| Portfolio | 并行生成 struct + noise，统一验证、按难度带选关 | 默认 |
| Structure-first + noise seasoning | 结构图 → SDF/宽度场扩散 → 有机形状 | hard/expert 视觉多样性 |
| Noise-first + injection | 岛型地形 → 骨架 → 注入缺失模式 | free / 探索 / 救急 |

## 6. 地形与塑形

### 6.1 岛型负空间

- 岛 = 不可达，缝隙 = 通路；天然产生岔路、瓶颈、回路。
- 噪声频率控制通道密度，阈值控制开放度，形态学控制最小宽度。
- 最大连通分量必须覆盖 S/E 和所有必经食物。

### 6.2 扩散 / 模糊

**不要**直接对二值占位图做高斯模糊 + 阈值。三种可选：

1. **SDF + 有界噪声**：`φ'(x) = φ(x) + α·n(x)`，`α < 局部特征尺寸`（约半个最小走廊宽）；低频噪声；阈值后校验骨架。
2. **骨架 + 宽度场扩散（首选）**：骨架图不变，只扩散中心线和宽度；栅格化后拓扑由骨架保证。
3. **模糊 + 拓扑修复（兜底）**：模糊阈值后检查连通分量/骨架，丢边重雕、捷径加墙。

结构完整性条件：

- 非连通走廊间距 ≥2 格；
- 闸门/瓶颈不参与模糊，保持 1–2 格清晰；
- 岔路几何保持可读；
- 扩散后骨架图与目标图同构，否则拒绝/修复；
- 优先各向异性扩散（沿走廊切向，不跨走廊）。

## 7. 谜题与放置

### 7.1 真假食物模型

| 类型 | 判据 | 作用 |
| --- | --- | --- |
| 真食物 | 精确求解证明“吃完后存在赢路”，且在主路线上 | 长度前沿，必吃 |
| 假食物 | 精确求解证明“吃完后无赢路”，且返回被封或长度不够 | 承诺陷阱，诱饵 |

关系：真食物**必需且充分**；假食物**诱人但不足/被封**。生成器用精确求解在分支上验证，不靠权重猜。

### 7.2 强制回头 / 环路截断

```text
(1) 单入口：环/死路只有一个接入点（割点）
(2) 必经食物：不吃分支内食物，主路线剩余走不完
(3) 可存活：a + C ≤ L
(4) 返回只能踩身体：单入口保证最后一步回到接入点就是截断
(5) 吃完后够用：主路线剩余 ≤ L
```

典型结构：

- `ForcedReturnDeadEnd`：死路 + 必经食物 + 踩身体返回；
- `FarForkFoodReturn`：近岔路走不出，远岔路取食后沿环回岔口截断；
- `TimedLoopTruncation`：生长相位使正确顺序唯一，晚一步封路。

### 7.3 闸门时机

```text
t_f = 玩家到达岔路时间
t_c = 进入分支后到达瓶颈时间
t_cover(c) = coverStep(c) · I

约束：t_f < t_cover(c) ≤ t_c
```

主线分支保持可走；机关等级/范围在岔路处可见。

### 7.4 参数约束

- `L0 / Gain / I` 极差 ≤5；
- 长度预算 `a + C ≤ L` 必须用真实规则计算；
- 生长间隔范围窄，闸门时间窗可计算；
- 参数多样性下降由拓扑/放置补偿，不靠参数极值拉难度。

### 7.5 模式组合

大/小模式可组合：

- normal：1 个小型路线或机关结构；
- hard：2 个大型结构，或 1 大 + 2 小；
- expert：3 个大型结构，或多个结构叠加后总分进 expert 带。

比例为初值，后续用批次与人工评分校准。

## 8. 求解与评分

### 8.1 节点抽象

```text
NodeState = (node, t, L, foodMask, g, phase, tailSummary)
```

- 节点：S/E、食物、机关瓶颈、岔路、环路交汇、死路端点；
- 宏边：无内部决策的走廊，带长度/宽度/门/食物；
- 宏边可行性：时间展开 / 精确局部规划；
- 状态支配：同一节点保留 Pareto 最优的 `(t, L, foodMask, phase)`；
- 流量先验：黏菌/势场只进 `Deception/Regret` 权重，不进可行性。

**注意**：顺序不是无关，而是被状态吸收；只记“到过哪些节点”会丢掉食物顺序、生长相位和身体几何。

### 8.2 节点自动判定

```text
P = 粗划分（房间 / 骨架交汇 / 瓶颈）
repeat:
  for each abstract edge on π*:
    if not realizable(P, edge):
      split the node by the failing state feature
until π* realizable or budget exhausted
nodes = P
D = refinements / radius / info
```

候选种子：割点/最小割/介数、landmark、决策熵、漏斗骤降点、资源转折点。最后合并“赢法相同”的节点，只保留高信息/高后悔节点。

这就是自动节点判定：**不是找一个固定启发式，而是让难度目标决定抽象粒度**。

### 8.3 难度指标

| 指标 | 含义 | 难度方向 |
| --- | --- | --- |
| `H_min / H_node` | 玩家前瞻阶梯 / 节点前瞻 | 越高越难 |
| `Regret` | 决策点错误代价 | 越高越难 |
| `Deception` | 诱人但必败的分支权重 | 越高越难 |
| `CounterfactualGap` | 删机关后是否仍轻松可赢 | 机关型必须为 1 |
| `GateNecessity` | 去掉单个机关后最优代价是否显著下降 | 越显著越必要 |
| `FunnelWidth` | 可行状态漏斗宽度 | 越窄越难 |
| `RouteTightness` | 路线上的漏斗紧度 | 越高越难 |
| `Forcedness` | 单合法步占比 | 高但不过 1 |
| `InfoRequirement` | `H(winning action \| node)` | 越高越难 |
| `TimingTightness` | 生长/闸门余量紧度 | 越高越难 |
| `TruncationTightness` | 强制截断/吃花续命紧度 | 越高越难 |
| `ConstraintSlack` | 长度/食物/闸门余量 | 越接近 0 越难，但不能越界 |
| `SolutionMultiplicity` | 胜利解多样性 | 越低越难，但不能为 0 |
| `NodeRadius` | 规范解可实现的最小容差 | 越小越难 |
| `StateSetSize` | 通过节点的状态数 | 越小越难 |
| `RefinementCount` | 抽象细化次数 | 越多越难 |

**目标带**：难度峰值在约束临界区，不是“所有节点单状态”的极紧端；唯一状态必须**非显然**（高信息要求/高后悔），否则只是被迫走廊。

### 8.4 评分公式

不再使用固定 `0.35·RouteScore + 0.65·DecisionScore` 的分割；纯路线也必须能到 100。

```text
sources = [
  w_route  · RouteTightness,
  w_forced · Forcedness,
  w_info   · InfoRequirement,
  w_regret · RegretNorm,
  w_time   · TimingTightness,
  w_trunc  · TruncationTightness,
  w_mech   · MechanismTightness
]

// 推荐：noisy-OR，平滑、单调、可组合
D_raw = 100 · (1 − Π_k (1 − s_k))

// 备选：max + 组合奖励，更易解释
D_base  = max_k(s_k)
D_bonus = β · count(s_k > θ)
D_raw   = min(100, 100·(D_base + D_bonus))
```

- `RouteScore`（步数/slack/食物紧度）降为**路线经济/质量**指标，不再承担主要难度权重；
- `MechanismTightness = Deception + CounterfactualGap + GateNecessity`；
- 纯路线结构由 `RouteTightness / Forcedness / InfoRequirement / Regret / TimingTightness / TruncationTightness` 计分；
- v5 分保留为诊断字段，双写；校准后再切生产；
- 权重/锚点待批次校准，不在单关上手调。

**反退化**：

- 长走廊 `Forcedness` 高但 `InfoRequirement` 低 → 不应高分；
- `InfoRequirement`/`Regret` 至少一个不低；
- `Forcedness` 接近 1 要降权，避免“唯一但被迫”。

### 8.5 纯路线高难案例

| 结构 | 难度来源 | 关键证明 |
| --- | --- | --- |
| `ForcedReturnDeadEnd` | 死路 + 必经食物 + 踩身体返回 | `ForcedReturnProof` + `LengthBudgetProof` |
| `FarForkFoodReturn` | 近岔路失败 + 远岔路取食 + 回岔口截断 | `OrderProof` + `LengthBudgetProof` |
| `TimedLoopTruncation` | 生长相位卡顺序 | `TimingProof` + `OrderProof` |
| `OrderedFoodChain` | 食物顺序影响长度/时机 | `OrderProof` + `LengthBudgetProof` |

这些结构不需要机关，也能通过 `RouteTightness / Forcedness / InfoRequirement / Regret` 拿到 hard/expert 分。

### 8.6 流量先验

- 用势场/流场/黏菌给“玩家最可能走哪条宏边”的先验；
- 只用于 `Deception` 权重、`Regret` 加权、诱饵吸引力；
- 不用于可解性、不用于 `H_min`、不用于公平性判定。

## 9. 验证门

```text
G0 硬有效性 → G1 拓扑/地形 → G2 结构/模式
→ G3 设计公平性 → G4 难度 → G5 分布/组合 → G6 确定性/预算
```

| 层 | 检查 | 失败动作 |
| --- | --- | --- |
| G0 | 可解、重放、连通、无非法重叠、参数极差、长度预算 | 拒绝 |
| G1 | 最大连通分量、间距、degree、最短路覆盖、无意外捷径、环数 | 修复/拒绝 |
| G2 | 模式存在、强制截断、闸门时机、真假食物、骨架同构 | 修模式参数/拒绝 |
| G3 | `DominanceGap`、`DecoyProof`、`GateNecessity`、`CanonicalNearOptimal` | 采纳更优解/封捷径/拒绝 |
| G4 | `H_min`、`Regret`、反退化、目标带、路线/机关证明 | 修参数/拒绝 |
| G5 | 双源比例、模式覆盖、新颖度、重复规避、档位配额 | 重采样/降级 |
| G6 | 同 seed 一致、工作单元上限、固定顺序 | 降档/兜底 |

### 9.1 设计公平性

信息全公开，所以不再检验“玩家能不能看懂”，只查设计有没有被绕过：

- `DominanceGap`：不存在 `cost ≤ cost(π*) − Δ` 的赢路；
- `DecoyProof`：每个诱饵在 `≤S+2` 内无赢路；
- `GateNecessity`：移除机关后最优代价显著下降；
- `CanonicalNearOptimal`：规范解不能明显劣于最优解。

旧的 `AUC` / `cue_coverage` / `reaction_window` / `ambiguity` 降为质量诊断，不再做硬门。

### 9.2 按难度来源分支

之前“normal+ 必须 `CounterfactualGap=1`”会误杀纯路线关卡，改为：

| 难度来源 | 必过门 |
| --- | --- |
| 机关型 | `CounterfactualGap` + `GateNecessity` + `DecoyProof` |
| 路线型 | `ForcedReturnProof` + `LengthBudgetProof` + `OrderProof` |
| 混合型 | 两者都过；可各自降级为“至少一个强项” |

### 9.3 路线型证明

- `ForcedReturnProof`：规范解必须进入死路/环路并踩身体返回；去掉食物后不可解或显著变难；
- `LengthBudgetProof`：`a + C ≤ L`、吃完后主路线剩余 ≤ `L`；
- `OrderProof`：替代顺序（先近岔路/后取食）在 `≤S+2` 内无赢路，或代价显著更差；
- `TimingProof`：`t_f < t_cover(c) ≤ t_c`；晚一步则封路。

### 9.4 验证顺序与预算

```text
所有候选：G0/G1/G2（O(N) / O(V+E)）
   → G3/G4 便宜代理（O(N) / O(T)）
   → Top-K：精确求解 + Counterfactual + 真假食物 + H_min/Regret
   → G5 选择（MAP-Elites）
   → G6 确定性/预算
```

早失败早丢弃；精确求解只跑 Top-K；`H>6` 或状态超预算时用 `H_witness` 并标记上界。

## 11. 实施阶段

| 阶段 | 内容 | 出口条件 |
| --- | --- | --- |
| P0 | 基线测量 + Portfolio 调度 + 结构注入 + 设计公平门 | 500 seeds/档基线；hard 中位数 +10；无不可解 |
| P1 | 结构图引擎（模式文法 + 嵌入）+ 节点抽象 | hard/expert 稳定进带；模式命中 ≥70% |
| P2 | 噪波负型引擎（岛场 + 骨架 + 注入）+ 融合 | 新类型覆盖 ≥5%；noise 通过率 ≥30% |
| P3 | 扩散塑形 + 分布控制 + 人工校准 | 结构关卡不重复；评分与体感 Spearman ≥0.7 |

### 11.1 P0 详细拆分

1. 用现有生成器跑 500 seeds/档，记录难度分布与失败原因；
2. 接入 `generation_source` 与调度比例；
3. 在现有地形上做结构注入：加 1–2 条假岔路、1–2 个闸门、封掉意外捷径；
4. 接入设计公平门：`DominanceGap` / `DecoyProof` / `GateNecessity`；
5. 输出基线报告，再决定 P1 参数。

## 13. 风险

- 门太多导致过度拒绝 → 修复优先、拒绝兜底、保留 `target_miss` 诊断；
- 结构图重复 → 参数随机化 + 扩散塑形 + MAP-Elites 多样性；
- 噪波成功率低 → 结构注入 + 降级；
- 扩散破坏拓扑 → 优先骨架+宽度场，SDF 扰动次选；
- 承诺陷阱挫败 → 只在 hard/expert 启用，必须有 pre-commit 线索；
- 计算成本 → 精确求解只跑 Top-K，状态上限 + 降级；
- 评分与体感不一致 → 先双写 v5/v4，人工校准后再切生产。
