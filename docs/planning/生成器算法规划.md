| 在范围内 | 不在范围内 |

**两条前提**：

1. 规则单一权威在 C# `RuleState`，生成器与游戏共用同一实现；生成的关卡必须能被 `RuleState` 重放通关。
2. **生成与分类解耦**：生成器不按「关卡原型」分支；原型/标签是生成完成、拿到解之后对关卡的**客观分类标注**。

## 2. 目标与验收口径

### 2.1 评分锚点

| 锚点 | 参照 | 分数 |
| --- | --- | --- |
| A0 | 空场直达（无阻挡、无机关、无花瓣） | 5 |
| A1 | `Level_01_move`（走过去） | 5 |
| A2 | `Level_02_petals`（散落的花瓣） | 10 |
| A3 | `Level_03_obstacles`（不能碰花） | 25 |
| A4 | `Level_04_GrowingFlowers`（花在变多） | 45 |
| A5 | `Level_05_CounterIt`（直面恐惧吧） | 100 |
| A6 | 生成上限档（30–45 步 + 尺寸 18–20 + 多结构叠加） | 180 |

- 分数为**绝对刻度**：下限 0（实际最低 5），软上限 200。
- 锚点用**同一套指标提取器**在 5 个手工关卡上实测一次，落成基线快照（`tests/fixtures/score_anchors.json`）；评分改动必须重跑快照。
- L2–L4 取 **10 / 25 / 45**，即整段落在 10~50 内，与 L5=100 之间留出明显断层（见 §2.4）。
- 断层区间（45–100）需要一个**实测中间锚点 A4.5**：取 S1 阶段真实生成批次中评分最稳的一批关卡的中位数，回填到样条里，避免该段只靠线性外推。

### 2.2 输出分布目标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 有效区间 | [5, 200] | 不出现负分 |
| 主体区间 `P(20 ≤ X ≤ 180)` | ≥ 95% | 极端关卡不超过 5% |
| **众数** | **75–85（目标 80）** | 落在要求的 70–130 内 |
| 中位数 | 82–92 | — |
| 均值 | 88–100 | 右偏导致均值 > 中位数 |
| 标准差 | 28–38 | — |
| 偏度 | +0.4 ~ +0.9 | 右偏，长尾朝 180 |
| `P(X < 20)` | ≤ 3% | 避免“白给关” |
| `P(X > 180)` | ≤ 2% | 避免不可解/不可玩 |
| **L5 分位** | **≥ 70%** | 第五关保持硬关定位 |

采样参考：偏正态 `μ≈88, σ≈30, α≈2.0`（右偏）时，众数 ≈ 78、中位数 ≈ 87、`P(20–180) ≈ 97%`，与上表自洽；最终参数在 S5 用实测分布拟合。

### 2.3 其他验收

- 连续 1,000 个 seed 全部可重放通关，生成失败率 0（极端地形降级返回存档最优，不报错）。
- 目标机生成耗时满足 §10 分档预算。
- 结构标签在 500 seed 批次中**覆盖率**达标（§7.4），用于反查生成旋钮是否够宽。
- 同一 `seed + tier + generator_version` 在任意机器上产出**逐字一致**的 `LevelSpec` 与路线。

### 2.4 L4→L5 断层的处理

锚点 45 → 100 意味着该段在原始难度指数上是**陡坡**：结构上微小差异会造成分数大幅跳动，生成关卡容易在 45 与 100 两侧堆积，直方图出现空洞（50–70 段稀疏）。

处理方式（不靠调分掩盖）：

1. **加密该段的指标分辨率**：`false_affordance`、`forced_truncations`、`gate_layers`、`end_slack` 四个细粒度指标（§5）在该段权重最高；
2. **回填 A4.5 实测锚点**，让样条在该段有真实参照；
3. **把直方图空洞列为 KPI**：500 seed 批次中 50–70 段占比 < 8% 视为不达标，回溯调整旋钮采样范围（§7.4）。

## 3. 现状与差距（2026-11-24 实测）

### 3.1 已有能力

- `RouteFirstGenerator`：CA 地形 + 真实 `RuleState` 随机行走 + 花瓣回填 + 后置机关验证 + 7 维评分，180 seeds 全部成功且可重放。
- 180 seeds（`Candidates=1`，`MaxAttempts=32`）：easy 均值 59.5、normal 65.9、hard 74.6；整体 min 48 / max 84 / stddev 8.3。
- 开发机性能：avg 7.26 ms、p95 28.65 ms、max 54.24 ms（12×12）。
- `LevelState.gd` 适配层、`ExactBfsSolver`、5 关黄金路线回归、导出冒烟均已就绪。

### 3.2 结构性差距

| # | 问题 | 位置 | 后果 |
| --- | --- | --- | --- |
| 1 | 花瓣饥饿驱动：`remaining<=0` 才回填，且每次回填整条重放 | `RouteFirstGenerator.cs` `RandomWalk` / `RebuildAndReplay` | O(S·F) 成本；花瓣全挤在濒死点；`tightness` 恒为 1 |
| 2 | 机关放在路线之后，每个候选整条重放 | 同上 `PlaceMechanisms` | 16×O(S)；只能放到“不破坏已验证路线”的位置，压力偏弱 |
| 3 | 机关初始等级恒为 0 | 同上 | 多机关**先后满级**的顺序压力完全没用上 |
| 4 | 诱饵只保证“离路线 2–4 格 + 净亏” | 同上 `AddDecoyFoods` | 造不出“看起来更短、实际必死”的假捷径 |
| 5 | 参数（L0 / Gain / I / cap）固定写在难度带 | 同上 `GetBand` | 每关参数不随机；一旦随机就触发问题 1 的成本爆炸 |
| 6 | 评分是 7 维归一化加权 ×100 | 同上 `ComputeScore` | 数学上限 100，永远到不了 180；且未计入误导性 |
| 7 | 热路径每次 `Step` 返回 Godot `Dictionary` | `RuleState.Step` | 每步多次 Variant 分配，GC 抖动 |
| 8 | 尺寸固定 12×12 | `GeneratorConfig` | 难度上不去，180 分不可达 |
| 9 | 生成器按“原型”预设驱动（上一版规划） | 本文旧 §7 | 生成多样性受限于预设，且预设与真实解可能不符 |

## 4. 设计原则

1. **测量分 / 目标分 / 存档分离**：`Difficulty` 只反映关卡本身；`TargetScore` 仅用于候选选择；MAP-Elites 存档保证多样性。禁止用分位数映射“凑”分布。
2. **生成与分类解耦**：同一套管线生成所有关卡；标签在拿到解之后计算，只做标注与统计，**不回流到同批生成**。
3. **确定性契约**：`seed + tier + generator_version` 决定关卡；搜索量以**工作单元**计量，墙钟只作熔断安全阀。
4. **生成永不失败**：极端情况下返回存档内离目标最近的关卡；仅当存档为空才降级到预烘焙 seed 包。
5. **结构优于参数**：难度来自结构叠加（假捷径 / 顺序压力 / 强制截断 / 尺寸），不是把步数调长。
6. **公平性**：任何“看起来能走其实必死”的结构，必须留下可观察线索（机关当前等级 / 已生长范围）；不做纯猜、不做信息隐藏。
7. **分层不变**：生成器只产出 `LevelSpec` + 路线，不碰节点 / 场景 / 信号。

## 5. 评分体系 v2

### 5.1 量化指标（19 项）

成本等级：**A** = 一次路线重放即可；**B** = 重放 + 少量 BFS / 策略模拟；**C** = 有界或精确搜索（仅 Top-K 与离线使用）。

| ID | 指标 | 定义 | 成本 | 说明 |
| --- | --- | --- | --- | --- |
| M01 | `steps` | 规范路线步数 S | A | 规模 |
| M02 | `min_slack` | 路线中最小剩余身长 `min(L - trail)` | A | 紧张度 |
| M03 | `end_slack` | 到达终点时的剩余身长 | A | 末段亏空 |
| M04 | `food_tightness` | 必经花瓣 / 总花瓣 | A | 资源约束 |
| M05 | `len_buffer` | `(L0 + Gain·F) / 净轨迹长` | A | 接近 1 = 长度极紧 |
| M06 | `forced_truncations` | 必需截断次数（不截断则必然超长） | A | 反直觉操作 |
| M07 | `detour_ratio` | `S / 静态最短路` | B | 绕行程度 |
| M08 | `corridor_ratio` | 路线中可走邻居 ≤1 的步数占比 | A | 通道压迫感 |
| M09 | `branching` | 路线格平均可走邻居数 | A | 选择密度 |
| M10 | `openness` | 可走格 / 总面积 | A | 空间感 |
| M11 | `mech_pressure` | 路线中 head 距任一机关中心 ≤2 的步数占比 | A | 时序压力 |
| M12 | `gate_layers` | 路线内机关等级增长出现的**不同 g 值个数** | A | 先后满级层数 |
| M13 | `late_growth` | 末 1/3 路线内是否仍有生长（0/1） | A | 尾段压力 |
| M14 | `false_affordance` | 假捷径诱饵数：`dist(b,d)+dist(d,E) ≤ 剩余步数-2` 且静态可达 E、且不在任何胜利路线 | C | 误导强度 |
| M15 | `mislead_gap` | 假捷径“看起来最多省下的步数” | B | 误导诱惑力 |
| M16 | `funnel_width` | 长度 ≤ S+2 的胜利路线数（对数分桶） | C | 解空间宽度 |
| M17 | `naive_fail_rate` | 3 个朴素策略（直奔终点 / 见花就吃 / 静态最短路）失败比例 | B | 反直觉程度 |
| M18 | `choice_entropy` | `Σ log2(k_t)`，`k_t` = 第 t 步合法方向数（可用“仍可解方向数”的近似） | B | 决策负荷 |
| M19 | `size` | 地图 `max(W,H)` | A | 规格因子 |

> 指标选择依据：谜题难度评测常用三类信号——**解的唯一性/解空间宽度**、**求解搜索量/搜索深度**、**逐步选择熵**；本表把它们落成可计算量，并补上本作特有的长度经济与时序维度（见 Sources）。

### 5.2 归一化

```
stepsN      = clamp01((S - 8) / 24)
slackN      = 1 - min(M02, 5) / 5
endSlackN   = 1 - min(M03, 4) / 4
tightN      = M04
bufferN     = 1 - clamp01((M05 - 1.0) / 0.5)
truncN      = min(M06, 3) / 3
detourN     = clamp01((M07 - 1.0) / 1.0)
corridorN   = M08
branchN     = 1 - clamp01((M09 - 1.0) / 2.5)
openN       = 1 - clamp01((M10 - 0.30) / 0.60)
mechN       = M11
gateN       = min(M12, 3) / 3
lateN       = M13
faN         = min(M14, 3) / 3
misleadN    = clamp01(M15 / 6.0)
funnelN     = 1 - clamp01(log10(max(1, M16)) / 3.0)
naiveN      = M17
entropyN    = clamp01(M18 / (1.5 * S))
sizeN       = (M19 - 10) / 10
```

### 5.3 原始难度指数与权重

```
D_core = 12·stepsN + 9·slackN + 4·endSlackN
       + 6·tightN + 5·bufferN + 6·truncN
       + 5·detourN + 3·corridorN + 2·branchN + 2·openN
       + 7·mechN + 6·gateN + 2·lateN
       + 5·sizeN
                                            // 0–74，全部为 A/B 成本，所有候选都算

D_raw  = D_core
       + 9·faN + 4·misleadN + 5·funnelN + 4·naiveN + 4·entropyN
                                            // 0–100，仅 Top-K 计算
```

- **两段评分**：所有候选先算 `D_core` 排序；Top-K（5–10 个）再补 C 类指标得 `D_raw`。
- 权重合计 100，是**初值**；只允许用批次回归调整（§5.5），不允许按单关手调。

### 5.4 锚点样条（D_raw → 分数）

用实测锚点做**单调分段线性插值**，而不是线性缩放：

```
锚点（D_raw 实测值 → 目标分）：
  D(A0/空场) → 5
  D(L1)      → 5
  D(L2)      → 10
  D(L3)      → 25
  D(L4)      → 45
  D(A4.5)    → 70      // S1 阶段回填的实测中间锚点
  D(L5)      → 100
  D(A6)      → 180
```

- 低于 `D(L1)` 一律取 5；高于 `D(A6)` 按最后一段斜率外推，上限 200。
- 样条节点必须**单调**：`D` 实测值若出现倒挂（例如 L4 的 D 高于 L5），说明指标设计有问题，先修指标再评分。
- 锚点是构造性精确的：5 个手工关卡在快照里就是精确命中 5 / 10 / 25 / 45 / 100。

### 5.5 质量分（与难度分离）

```
Quality = 100 · ( 0.35·cue_coverage
                + 0.25·structure_signal
                + 0.20·visual_distinguishability
                + 0.20·route_uniqueness )
```

| 分项 | 定义 | 检查目的 |
| --- | --- | --- |
| `cue_coverage` | 影响路线的机关中，玩家在必经路径上可观察到其当前等级的比例 | 误导是否公平 |
| `structure_signal` | 标签是否由 ≥2 个独立指标共同支持 | 避免偶然标签 |
| `visual_distinguishability` | 对称/相似分支是否存在可观察差异 | 避免纯猜 |
| `route_uniqueness` | `funnel_width` 分桶映射 | 解是否够收敛 |

难度高但质量低（纯靠死角堆步数、纯靠不可读差异）的关卡应被丢弃或降权。

### 5.6 校准流程

1. 跑 5 个手工关卡 → 指标向量 → 锚点快照；
2. 跑 500 seeds → `D_core` / `D_raw` / 分数分布；
3. 调整权重与**旋钮采样范围**（不是分位映射）；
4. 重复 2–3，直到 §2.2 全部达标；
5. 权重、快照、样条节点一起提交，作为回归基线。

## 6. 目标分布与尺寸

### 6.1 目标采样

```
每关生成前：
  target = SkewNormal(μ≈88, σ≈30, α≈2.0).Sample(rng)
  若 target < 20 或 > 180 则重采样（拒绝采样，避免端点堆积）
  tier = 按 target 分位：easy=P20 / normal=P50 / hard=P85 / expert=P97
```

生成结束后从 MAP-Elites 存档中选 `argmin |Difficulty - target|` 的格子；该目标区间无可用格子时按容量权重回退到最近格子，并记录 `target_miss`。

### 6.2 尺寸：难度因子（上限 20×20）

尺寸是**独立难度因子**（`sizeN`），同时约束路线长度上限。阶梯（均在 20×20 以内）：

| 尺寸 | 可承载分数 | 典型路线 | 说明 |
| --- | --- | --- | --- |
| 10×10 | 5–35 | 8–12 | 教学 / 低分段 |
| 12×12 | 10–60 | 10–18 | 现有基线 |
| 14×14 | 30–90 | 14–24 | 中段主力 |
| 16×16 | 50–120 | 18–30 | 高分段 |
| 18×18 | 70–150 | 22–36 | 尾部 |
| 20×20 | 90–180 | 26–45 | 极限档，仅 Loading 预算 |

规则：

- 目标分决定尺寸采样区间（高分可低尺寸，但概率低）；
- 大尺寸必须同时满足 `floor_count ≥ targetSteps + 8`，否则降一档尺寸重试；
- 生成成本按面积缩放：20×20 约为 12×12 的 2.8 倍，工作单元需同步换算（§10）。

### 6.3 可达性与不可达处理

- 先扩尺寸与旋钮采样范围，再回退目标分；
- 连续 20 次 `target_miss` 视为该分数段不可达，降低该段采样概率并记日志；
- 禁止修改 `Difficulty` 公式来“补洞”。

## 7. 关卡标签体系（事后分类）

> **核心约定**：标签是**生成完成、拿到解之后**的客观分类结果，不参与生成决策。生成器不读标签，也不为凑某个标签而重试。

### 7.1 标签定义与判据

| 标签 | 判据（全部由 §5.1 指标或解的结构给出） | 需要的成本 |
| --- | --- | --- |
| `false_shortcut` | `M14 ≥ 1` 且 `M15 ≥ 2` | C |
| `gate_sequence` | `M12 ≥ 2`（≥2 个不同生长轮次触发机关升级/满级） | A |
| `forced_truncation` | `M06 ≥ 1` | A |
| `overshoot_return` | 规范路线中 `dist(head,E)` 相比最小值增加 ≥3 后才下降 | A |
| `mirror_fork` | 存在两段 ≥4 格的静态可对称分支，且仅一侧动态可行 | B |
| `mutual_exclusion` | 存在两片诱饵：各自单独可吃，但不存在双吃胜利解 | C |
| `body_key` | 解中某步依赖“身长恰好 ≥N 挡格”或“恰好 ≤M 过窄道”，可行窗口 ≤2 | B |
| `last_gasp` | 末 3 步内发生机关生长并通过 | A |
| `tight_budget` | `M03 ≤ 1` | A |
| `no_mechanism` | 机关数 = 0 | A |
| `dense_maze` | `M10 ≤ 0.35` | A |

多标签并存；每关输出 `tags[]` 与每个标签的**证据字段**（涉及的指标值 / 格坐标 / 步序），便于 QA 复核。

### 7.2 标签的三种用途

| 用途 | 说明 |
| --- | --- |
| 多样性统计 | 批次内标签覆盖率、共现矩阵；反映生成器旋钮够不够宽 |
| MAP-Elites 描述符 | 存档按 `(尺寸, 步数桶, min_slack 桶, mech_pressure 桶)` 分格，标签作为附加检索维度（分类在评分之后，不影响生成） |
| QA 抽样 | 每个标签抽 N 关人工验收，重点检查公平性与可读性 |

### 7.3 分类器实现位置

- 纯 C#：`Scripts/Algorithms/Scoring/LevelTagger.cs`（只读 `RuleState` 快照 + 指标向量，不碰节点）；
- 输出写入 `LevelScore.Tags` 与 `LevelSpec.Tags`；
- 单关分类成本目标 ≤ 2 ms（C 类指标复用 Top-K 已算结果，不重复求解）。

### 7.4 覆盖率 KPI 与旋钮反馈

- 500 seed 批次中，结构标签（`false_shortcut` / `gate_sequence` / `forced_truncation` / `overshoot_return` / `mirror_fork`）各自覆盖率 **≥ 5%**；
- 覆盖率不足时，**调旋钮**（例如提高机关 `initial_level` 非零采样概率、提高诱饵候选数、放宽 waypoint 折返次数），而不是新增“按原型生成”的分支；
- 覆盖率过高（> 40%）同样视为旋钮过窄，需要拉开参数分布。

## 8. 参数体系

### 8.1 每关独立参数

| 参数 | 取值 | 作用 | 权威出处 |
| --- | --- | --- | --- |
| `initial_max_len` (L0) | 3–7 | 开局身长 | 功能需求 §7，关卡可覆盖 |
| `food_len_gain` (Gain) | 2–4 | 单片花瓣价值 | 功能需求 §7，关卡可覆盖 |
| `growth_step_interval` (I) | 4–8 | 生长节奏 | 功能需求 §7，关卡可覆盖 |
| `mechanism_max_level` (cap) | 1–4 | **关卡级**最高阶段 | 功能需求 §4.2.5 / §7 |
| `initial_level[k]` | 0–cap | **机关级**初始阶段，决定各自满级时刻 | 功能需求 §4.2.5 |
| `map_size` | 10×10 – 20×20 | 难度因子 | 功能需求 §7（网格大小） |

`initial_level` 与 `cap` 是**两个独立口径**：`cap` 整关统一，`initial_level` 逐机关指定；机关 k 在 `(cap - a_k)` 次生长后满级。生成器据此让多机关形成先后满级的时间压力——这是纯粹的参数采样，不需要任何新规则。

### 8.2 可行域代数（采样后立即过滤）

```
F_req = ceil((S_eff - L0) / Gain)            // 必需花瓣数
S_eff = 终点净轨迹长 - 1                      // 截断已扣减

约束：
  F_req ≤ 5                                   // 花瓣不能过密
  F_req ≤ floor(S / I) + 1                    // 相位数装得下
  I * (cap + 1) ≤ S                           // 机关必须真正满级
  S_eff - L0 ∈ [Gain, 4·Gain]                 // 末段余量合理
  cap - a_k ≥ 1                               // 至少一层成长空间
  S ≤ 0.9 * floor_count                       // 路线要留出绕行余量
```

不满足则重采样参数元组（O(1)），不进入行走阶段。

### 8.3 `LevelSpec` Schema v2

在现有字段（`SchemaVersion=1`）基础上追加，`FromJson` 对 v1 缺失字段取默认值：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `schema_version` | int | 升到 2 |
| `generator_version` | string | 语义扩展为“含评分与标签版本” |
| `tier` | string | `easy / normal / hard / expert` |
| `tags` | string[] | **事后分类结果**（只读标注） |
| `tag_evidence` | object | 每个标签的证据字段 |
| `target_score` | int | 生成时的目标分（可追溯） |
| `budget_units` | int | 实际消耗的工作单元数 |
| `param_signature` | string | `L0|Gain|I|cap|a_k` 的规范串 |

## 9. 生成管线 v2（9 阶段）

| # | 阶段 | 输入 | 方法 | 输出 | 成本 | 失败策略 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 目标与尺寸 | seed、tier | 偏正态采样 target；按 §6.2 采尺寸 | `(target, size)` | O(1) | 拒绝重采样 |
| 2 | 参数采样 | 上一步 | §8.1 采样 + §8.2 代数过滤 | `(L0, Gain, I, cap, a_k)` | O(1) | 重采样 |
| 3 | 地形 | rng、尺寸 | CA + 低频噪波房间/走廊 + 最大连通分量 | `Floor` / `Obstacles` | 低 | 换 fill 重试 |
| 4 | 路线构建 | 地形、参数 | 相位排花（`F_req` 反解）+ 偏置随机行走 + 可选 waypoint（折返/截断） | 路线 | O(S) | 换起点重试 |
| 5 | 机关与诱饵落位 | 路线、参数 | 机关蓝噪声撒点（含 `a_k`）+ 诱饵候选（假捷径判据） | 实体集合 | O(S) | 允许 0 机关 / 0–2 诱饵 |
| 6 | 验证 | 完整 spec | 时间窗增量验证 + 1 次完整重放；Top-K 过 `solve_exact` | 合法 spec | O(S) + 5–10 次精确解 | 丢弃候选 |
| 7 | 评分 | spec、路线 | `D_core` → Top-K → `D_raw` → 锚点样条 | `LevelScore` | 中 | — |
| 8 | **标签分类** | spec、路线、指标 | §7.1 判据 | `tags[] + 证据` | ≤2 ms | 无标签也合法 |
| 9 | 入档与选格 | score、tags | MAP-Elites 存档 → 选离 target 最近的格子 | 最终关卡 | O(1) | 回退最近格 |

## 10. 性能预算与调度

### 10.1 分档预算

| 档位 | 触发 | 目标机预算 | 开发机等效(÷2.5) | 工作单元上限（12×12 基准） | 玩家可见延迟 |
| --- | --- | --- | --- | --- | --- |
| `Bootstrap` | 首关、无缓存 | 120 ms | ~48 ms | 1 候选 / 1 次构建 | 仅一次 |
| `Background`（默认） | 玩家解当前关时生成下一关 | 1500 ms | ~600 ms | 3,000 attempts 或 400 rollouts | 0 |
| `Loading` | 关卡间加载屏 + 小游戏 | 4000 ms | ~1600 ms | 10,000 attempts 或 1,200 rollouts | 被小游戏吸收 |
| `Prefetch` | 空闲 | 队列深度 3 | — | 每帧 2–4 ms 时间切片 | 0 |

**尺寸换算**：工作单元按面积折算——`units ∝ (W·H) / 144`。20×20 的 400 格约为 12×12 的 2.8 倍，同等墙钟预算下可跑次数约为 1/2.8。

### 10.2 确定性

- 预算以**工作单元**固定，墙钟仅作熔断；
- 熔断触发时记录 `budget_aborted=true`，**确定性降一档**重跑（使用该档固定工作单元），不返回随机中间态；
- `generator_version` 变更必须同时更新锚点快照与回归基线。

### 10.3 线程与内存

- 生成器内部只用纯 C# 类型（`Cell` / `List<Cell>` / `Span`），结束才转 `Godot.Collections`；可在 `Task.Run` 后台执行。
- 复用 `RuleState` 实例（新增 `ResetToSpec`），避免每次 `Setup` 重建集合。
- 禁止在生成热路径 `new Dictionary`；路线/轨迹用 `List<Cell>` 复用池。
- 单关生成内存目标 < 8 MB。

### 10.4 缓存与预取

- 缓存路径：`user://generated/{seed}_{tier}_{generator_version}.json`；
- 预取队列深度 3，进入关卡即请求下一关；
- 缓存命中直接 `LevelSpec.FromJson`，0 ms 生成；
- 缓存淘汰按 LRU，上限 50 个。
