## 1. 现状与关键结论

### 1.1 已有基础

- `LevelState`：纯规则状态层，游戏与求解器共用；已用 `cover_step + shielded` 等价旧机关补占逻辑。
- `LevelSolver`：离线 BFS 可解性/路线求解器，支持路线回放校验。
- 5 个手工关卡、主菜单、选关、HUD、暂停、剧情、音频、存档。
- 当前分支 `feat/level-state-solver` 已有提交 `refactor: 抽取纯规则层为 LevelState，新增离线求解工具`，待评审后合并主线。

### 1.2 求解器性能实测

| 场景 | 状态数 | 耗时 | 结果 |
|---|---:|---:|---|
| 手工 Level 1 | 5,406 | 57 ms | SOLVABLE |
| 手工 Level 2 | 3,585 | 47 ms | SOLVABLE |
| 手工 Level 3 | 7,448 | 110 ms | SOLVABLE |
| 手工 Level 4 | 20,724 | 355 ms | SOLVABLE |
| 手工 Level 5 | 59,532 | 1,085 ms | SOLVABLE |
| 32×1 走廊 + 食物链 | 202 | 3 ms | SOLVABLE |
| 开阔 12×12 + 食物链 | 200,003 | 2,360 ms | UNKNOWN（超预算） |
| 开阔 16×16 + 食物链 | 200,003 | 2,423 ms | UNKNOWN |
| 开阔 32×32 + 食物链 | 200,001 | 2,483 ms | UNKNOWN |

结论：

- 当前 GDScript 精确 BFS 吞吐约 **5～8 万状态/秒**，适合**封闭小图/最终 QA**，不适合 32×32 开阔图的生成过滤。
- **迁移 C# 后实测**（同一 5 关，引擎内 headless，含首次 JIT）：24 / 3 / 9 / 41 / 142 ms（总计约 219 ms）；对应 GDScript 57 / 47 / 110 / 355 / 1,085 ms（总计约 1,654 ms），**整体约 7.5×**（第 1 关含 JIT 预热，稳定态更快）。
- 临时宏规划器在相同开阔图上找到解：12×12 约 4 ms、16×16 约 8 ms、32×32 约 81 ms（未做完整死局/机关校验，仅证明"找解"成本远低于"穷举"）。
- 因此正式版的算法策略必须是**分层/混合**：
  - 找解：FastPlanner / Weighted A\* / Beam Search。
  - 证明：小图 BFS、离线 SAT/CP/ASP；32×32 开阔图不做穷举证明。
  - 生成：route-first 构造，不依赖拒绝采样。

### 1.3 正式版约束

- 32×32 是**画布**，建议实际可走区 60～180 格（岛/房间/走廊），而不是整块开阔地。
- 生成模式必须保证"产出的关卡有解"；用规范路线重放作为证书，而不是依赖 BFS 判定。
- 所有面向玩家的性能必须在低配目标机上可接受；算法核心需可替换/加速。

### 1.4 算法改造进度（2026-11-27）

- 运行时生成链路已打通：主菜单/接力 → 加载屏分帧 → `GenerationService` 后台线程 → 生成缓存 → `Level.gd` 直接消费 `LevelSpec`（未拆独立 `LevelBuilder`）；`--generated-smoke` headless 可连续跑通 4 关。
- 生成器当前实现 v15：自适应候选预算、Portfolio 调度、结构注入（死胡同假岔路）、设计公平门、端点/诱饵的临时位置修正、S/E 求解次数收敛均已落地（完整批次待复测）。
- **P0 出口未达成**：只有 30 seeds/档批次（120/120 可解），500 seeds/档未跑；hard 中位分未 +10。**P1 结构图引擎未开始**。
- 方向修正：端点与诱饵不再靠事后约束，改为由结构图（S/E 与承诺陷阱作为节点）在生成阶段产出。详见 [随机关卡算法 v4](随机关卡算法v4-整体改造方案.md) §11.2。

## 2. 目标架构

### 2.1 语言与职责边界

```text
GDScript（表现层 / 引擎接入）
  ├─ Level / LevelView：场景、节点、信号、动画、HUD
  ├─ LevelState.gd：薄适配层（字段同步 + 转发 C# RuleState；不含规则）
  ├─ LevelBuilder：运行时把 LevelSpec 构建成场景/图层/实体
  ├─ HintArrows：路线箭头表现
  └─ UI / 设置 / 存档 / 输入 / 本地化

C#（规则与算法，单一权威，项目内 Scripts/Algorithms/）
  ├─ RuleState：玩法规则唯一实现（移动 / 截断 / 生长 / 死局）
  ├─ GridModel / MechanicShapes：网格与形状
  ├─ ExactBfsSolver：精确求解
  ├─ FastPlanner：宏规划 + 时间窗 BFS
  ├─ Generator：route-first 种子生成
  └─ Metrics / Scoring：双维度评分
```

硬约束：

- GDScript 是**引擎接入层唯一入口**；C# 不直接操作节点/场景/信号，只做纯数据计算。
- 玩家实际移动、胜负、动画的**规则判定**由 C# `RuleState` 决定，`Level.gd` 只负责表现同步；GDScript 不再保留规则副本。
- 生成器 / 求解器返回的路线必须经同一 `RuleState` 重放校验；校验失败视为算法错误，不直接采信。
- 算法异常时必须降级：手工战役关可玩，提示可退回预烘焙路线；生成模式提示"生成不可用"，不得崩溃游戏。

### 2.2 运行时生成数据流

```text
Seed + RunConfig
   ↓
C# Generator（Scripts/Algorithms/）
   ├─ LevelSpec（地板/障碍/S/E/食物/机关/参数）
   ├─ Solution（规范路线 + trace + events）
   └─ Score（难度/质量/明细）
   ↓
GDScript LevelBuilder
   ├─ 构建 Ground/Obstacles/EntityRoot
   ├─ 初始化 LevelState.gd（内部 C# RuleState）
   └─ 把 trace 交给 HintArrows
   ↓
C# RuleState 重放 Solution（经 LevelState.gd 适配层）
   ├─ 成功 → 开始关卡
   └─ 失败 → 记录遥测 + 换下一个 seed（有界重试）
```

### 2.3 推荐目录

```text
Scripts/
  Algorithms/            # C#：规则与算法（单一权威）
    RuleState.cs         # 玩法规则唯一实现
    GridModel.cs         # 网格数据 + BFS
    MechanicShapes.cs    # 机关形状 / cover_level
    Search/ExactBfsSolver.cs
    Search/FastPlanner.cs        # 后续
    Generation/                  # 后续
  Systems/LevelState.gd  # 薄适配层（API 不变）
  Systems/LevelBuilder.gd
  Systems/HintArrows.gd
  Data/LevelSpec.gd / LevelSolution.gd
tests/
  core/CoreTests.tscn    # C# 断言 runner（headless，退出码判定）
  fixtures/levels_expected.json   # 迁移前黄金路线快照
  fixtures/anchors/ · fixtures/bench/   # 锚点 / 基准快照
Scenes/
  Levels/GeneratedLevel.tscn   # 生成模式通用场景
```

## 3. 算法方案摘要

| 算法 | 用途 | 优点 | 局限 |
|---|---|---|---|
| FastPlanner（宏规划 + 时间窗 BFS） | 生成、提示、评分初筛 | 毫秒级，贴合本作结构 | 不完备，需要重放校验 |
| Weighted A\* / IDA\* | 通用找解、提示重算 | 有目标启发，比 BFS 快 | 证明无解仍可能穷举 |
| Beam Search / LDS | 多解、评分、陷阱统计 | 快，能找不同路线 | 不完备 |
| 精确 BFS | 小图/QA 证明 | 完备、实现简单 | 状态爆炸，不适合 32×32 开阔图 |
| SAT / CP-SAT / ASP | 离线批量证明 | 可证明有解/无解 | 编码复杂、外部依赖 |
| MCTS / RL | 不推荐 | 能处理大分支 | 无完备性、训练成本高 |

正式版默认流水线：

```text
FastPlanner → Weighted A*（有界）→ Exact BFS（小图）/ CP-SAT（离线）
```

## 6. 性能预算

| 项 | 预算 | 说明 |
|---|---|---|
| 运行时生成 | 分档：120 / 1500 / 4000 ms | 目标机；详见 [生成器算法规划](过时/生成器算法规划.md) §10 |
| 提示首次规划 | < 100 ms | 可在加载时预计算 |
| 手动重新提示 | < 100 ms | FastPlanner/有界 A* |
| 关卡加载 | < 300 ms | 含 UI/资源 |
| 帧率 | 稳定 60 FPS | 低配目标机 |
| 单次精确 BFS | 小图 < 1 s | 状态 < 80k；否则 UNKNOWN |
| 批量生成 | 离线 | 1,000 seeds 可分批；不阻塞游戏 |

约束：

- 游戏运行时**不跑完整精确 BFS**；提示/生成走 C# FastPlanner/有界搜索。
- 算法调用不得每帧发生；路线在关卡开始/重新提示时计算；适配层只做标量/小数组同步，避免高频 GC 分配。
- 32×32 可走区建议 60～180 格；L_max ≤ 11～13；食物 2～5；机关 1～3。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 规则迁移偏差 | 迁移后行为与旧版不一致 | 迁移前黄金路线快照 + 逐函数对照 + 用户试玩 |
| .NET/mono 导出与运行时依赖 | 安装包体积增大、平台受限 | 统一 mono 模板；放弃 Web 导出；CI 做导出冒烟 |
| 主机/移动端 .NET 支持 | 平台受限 | 先定平台优先级；按 Godot .NET 官方支持范围规划 |
| seed 版本漂移 | 每日榜/分享失效 | 固定 generator_version；排名存完整 Spec |
| 生成关卡质量差 | 玩家挫败 | route-first、评分带、试玩、失败原因提示 |
| 低配机性能 | 掉帧/生成卡顿 | 预算、异步、C# 加速、可走区限制 |
| 在线排行榜作弊 | 榜单不可信 | 若做在线，服务端用同一 C# `RuleState` 重放复核 |
| 范围膨胀 | 延期 | P0/P1/P2 分级；里程碑出口条件 |
| 本地化/字体缺字 | 显示异常 | 字体覆盖检查、字符串表、回退字体 |
| 存档不兼容 | 玩家进度丢失 | 版本化 + 迁移 + 备份 |
