# 评分算法 v3 重构规范与清单

> 状态：**规划稿（非权威）**。本文只描述评分算法的实现方案，不改变玩法规则；锚点数值来自用户主观体感（定性），最终以人工验收为准。规则以 [功能需求文档](../design/功能需求文档.md) §4 / §7 为准。
>
> 关联：[生成算法 v3 规范与清单](生成算法v3重构规范与清单.md) · [算法执行状态机](算法执行状态机.svg) · [生成器算法规划（v2，历史）](生成器算法规划.md)

## 0. 摘要与已确认决策

**一句话：** 从“路线长度 + 机关邻近度”的静态评分，改为“交互差距 + 最小前瞻深度 `H` + 公平性”的复杂度评分；用 L1–L5 的 **5 / 15 / 30 / 40 / 75** 拟合单调校准曲线，生成关卡只使用拟合后的函数输出。

已确认（2026-11-25）：

| 决策 | 结论 |
| --- | --- |
| 机关压规范路线 | 接受；评分必须反映“机关真实改变了决策”，而不是机关贴着路线 |
| 公平性 | 采用图扩散得到感知危险场，再用 AUC / 模糊隶属度判定；不公平的候选直接淘汰 |
| 锚点 | 5 / 15 / 30 / 40 / 75 是 L1–L5 的定性总分；先拟合，再用拟合后的分值作为实际分数 |
| 神经网络 | 运行时不使用；用图扩散 + 模糊推理 + 单调校准（PCHIP / isotonic） |

## 1. 背景：当前评分为什么虚高

当前口径：

```text
core = clamp01(DCore / 65) × 100
Hybrid = 0.55 × branch + 0.45 × core
Score = round(clamp(raw + 7, 0, 200))
```

问题：

| 问题 | 位置 | 后果 |
| --- | --- | --- |
| `DCore` 权重里步数、尺寸、机关邻近度占比高 | `MetricExtractor` §5.3 | 20×20、30 步的图很容易把 `DCore` 顶到 65，`core` 饱和到 100 |
| `mech_pressure` 是“距机关中心 ≤2 的步数占比” | `MetricExtractor` M11 | 机关贴着路线但从不封路，也会拿满 |
| `branch` 由独立参数的黏菌网络计算 | `BranchPosteriorScorer` 480/260/0.62 vs 600/300/0.55 | RouteFirst 关卡也能测出很高“假主干质量” |
| 没有基线扣除 | `ComputeScore` / `ApplyBranchScore` | 路线本身的长度/绕行被算进难度，无法区分“纯规划”与“交互” |

结果：分数可以到 90–100，体感却接近 L3。v3 的目标是让**纯路线规划关卡的交互分接近 0**，难度只来自身体与机关的竞争。

## 2. 形式化定义

### 2.1 可行核与 slack

沿用生成算法 v3 的三层模型：

```
R0：时间展开（只看地形 / 机关）
R1：+ 身长资源（dist_{G\O}(S,v) ≤ L0 + ΔL·k − 1）
R2：精确轨迹（截断 / 屏蔽）
R2 ⊆ R1 ⊆ R0
```

对 R1 做后向 DP：

```
Latest(v, k) = max{ t : 从 (v,t,k) 仍能到达 E }
slack(v,t,k) = Latest(v,k) − t
ViableKernel = {(v,t,k) : slack ≥ 0}
```

`Δ = R1 \ R2` 是欺骗空间：看起来可达、实际不可赢。

### 2.2 最小前瞻深度 `H`（主指标）

对规范解 `π` 上的状态 `σ`：

```
d(σ) = 最小的 d，使得从 σ 做深度 d 的精确搜索能找到一步赢着
H(Λ) = min over winning π of max over σ∈π d(σ)
```

含义：**这关至少需要向前看多少步**。

- `d = 1`：贪心/静态规划就能过；
- `d = 4`：必须在 4 步前预判机关生长；
- `d = ∞`：需要全局搜索/完整可行核。

**可计算近似：** 用 `ExactBfsSolver` 给出的规范路线 `π*` 作为见证，计算

```
H_witness = max_{σ∈π*} d(σ)
```

它是 `H` 的上界（因为 `π*` 不一定是使 `max d` 最小的赢路）。评分默认使用 `H_witness`，并在结果中标记 `h_is_upper_bound = true`；生成器可以用它作为目标值。

### 2.3 交互指标

| 指标 | 定义 | 复杂度 |
| --- | --- | --- |
| `H` | 见 §2.2；按阶梯 `{0,1,2,3,4,6,8,∞}` 计算 | `O(T·4^H)` / 策略 |
| `Deception` | 规范解沿途“局部更优但不在可行核内”的决策数 × 承诺深度，归一化 | `O(B·4^d)` / 决策，`d` 有界 |
| `Cuts` | 生长事件使可行核缩小、或封死一条可行分支的次数 / 总生长事件 | `O(F·V·T)`（复用表） |
| `Contention` | 生长事件中身体屏蔽 ≥1 个机关格、或机关封死可行分支的次数 / 总生长事件 | 精确重放 `O(T)` |
| `L_tight` | 被迫截断次数 + 依赖吃花才能继续的段数，除以 `T` | 精确重放 `O(T)` |

**Deception 的“吸引力”定义（初值）：**

```
attractive(b) = 静态距离(b → E) ≤ 规范解剩余距离 − 2
unsafe(b)     = 从 b 出发在 R2 中无赢路
commit(b)     = 从选择 b 到该分支被完全封死之间的步数
Deception     = Σ_{b attractive & unsafe} min(commit(b), H_max) / (T·H_max)
```

**Cuts 的定义（初值）：**

```
Cuts = (# 生长事件 t，使 ViableKernel_t \ ViableKernel_{t−1} 包含
        规范解之外的可行分支) / (# 生长事件)
```

**Contention 的定义（初值）：**

```
Contention = (# 生长事件中 trail 屏蔽了机关格
              + # 生长事件中机关封死了可行分支) / (# 生长事件)
```

### 2.4 基线扣除

```
D_raw(Λ) = 100 × (0.40·H_norm + 0.20·Deception
                + 0.15·Cuts + 0.15·Contention + 0.10·L_tight)
D_interaction(Λ) = max(0, D_raw(Λ) − D_raw(Λ_without_mechanisms))
```

- `Λ_without_mechanisms`：同样地形、S/E、食物，删除所有机关；
- 纯路线规划关卡：两者接近，`D_interaction ≈ 0`；
- 机关只影响身后的关卡：`D_interaction` 仍然很低；
- `H_norm = min(H, 8) / 8`。

### 2.5 公平性

与 [生成算法 v3](生成算法v3重构规范与清单.md) 共用感知危险场：

```
f^(0)(v) = 1 if v ∈ M(t) else 0
f^(k+1)(v) = (1−η)·f^(k)(v) + η·mean_{u~v} f^(k)(u)
P(v,t) = clamp(w_s·f^(K)(v) + w_t·μ_cover(v,t))
```

- 图扩散只在可走图上进行；墙为 Neumann 边界，禁止穿墙；
- 对规范解沿途每个决策点的合法分支 `b`，计算 `P_b` 与 `unsafe(b)`；
- `AUC`：用 `P_b` 预测 `unsafe(b)`；
- `μ_fair(b) = smoothstep((P_b − P_safe + δ)/δ)`；
- 公平性是**有效性约束**，不是难度分项：`AUC < θ_A` 或 `μ_fair < θ_F` 的关卡不进入正式结果，但仍可输出诊断字段。

## 3. 规范

### 3.1 评分公式

```text
D_raw = 100 × (0.40·H_norm + 0.20·Deception
             + 0.15·Cuts + 0.15·Contention + 0.10·L_tight)

D_interaction = max(0, D_raw(Λ) − D_raw(Λ_without_mechanisms))

Score = clamp(f(D_interaction), 0, 100)
```

- `f` 是离线拟合的单调函数（见 §3.3），运行时只查表；
- `Score` 是生成器与 HUD 使用的唯一分数；
- `D_raw`、`H`、`Deception`、`Cuts`、`Contention`、`L_tight`、`FairnessAUC` 作为诊断字段保留；
- `Steps`、`Size`、`Openness`、`MechPressure` 降为门槛/诊断，不再进入主分。

### 3.2 `H` 的计算

- 阶梯：`{0, 1, 2, 3, 4, 6, 8, ∞}`；
- 对每个阶梯 `h`，从规范路线起点做“深度 `h` 精确搜索 + R1 启发式”的策略；
- 若策略赢，取最小 `h`；若 `h = ∞`，调用 `ExactBfsSolver`；
- 记忆化：以 `(head, trail 摘要, g, food 摘要)` 为键，避免重复搜索；
- 复杂度：`O(T·4^h)` / 策略；`h ≤ 8` 时可控；超过 8 直接记 `H = ∞`（或用精确求解的状态数作为替代难度）。
- 结果标记：`h_is_upper_bound`（用规范路线见证）。

### 3.3 校准：5 / 15 / 30 / 40 / 75

**输入锚点（定性）：**

| 关卡 | 锚点 |
| --- | --- |
| L1 `Level_01_move` | 5 |
| L2 `Level_02_petals` | 15 |
| L3 `Level_03_obstacles` | 30 |
| L4 `Level_04_GrowingFlowers` | 40 |
| L5 `Level_05_CounterIt` | 75 |

**流程：**

1. 用新口径计算 `D_interaction(L1) … D_interaction(L5)`；
2. 检查严格递增；若倒挂，先修指标（特征 / 权重），不得用拟合掩盖；
3. 用 **PCHIP（分段三次 Hermite 单调插值）** 拟合 `(D_interaction(Li), anchor_i)`；
4. 若锚点被视为带噪声的定性样本，可先用 **isotonic regression** 得到单调序列，再用 PCHIP 平滑；拟合后的值替代原始锚点；
5. 运行时 `Score = clamp(PCHIP(D_interaction), 0, 100)`；
6. 生成器只使用 `Score`，不再使用 5/15/30/40/75 作为阈值。

**两种模式：**

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| `interpolate` | PCHIP 严格过 5 个锚点 | 锚点可信、希望精确复现 |
| `fit` | isotonic + PCHIP，输出拟合值 | 锚点定性、希望平滑；默认 |

**档位（初值）：**

```text
Easy    < 10
Normal  10 – 35
Hard    35 – 58
Expert  ≥ 58
```

这是 5/15/30/40/75 的中点初值，需人工试玩后调整；也可以改用三角隶属度的模糊档位，避免硬边界跳变。

### 3.4 数据结构与接口

```text
ScoreInput {
  spec, route, target_steps,
  r1_table (optional), perceived_field (optional),
  h_target, fairness_theta_a, fairness_theta_f
}

ScoreResult {
  score, raw_interaction, raw_level, raw_baseline,
  h, h_norm, h_is_upper_bound,
  deception, cuts, contention, l_tight,
  fairness_auc, fairness_min,
  scoring_version, calibration_mode, anchor_set
}
```

- JSON 字段使用 snake_case；
- `scoring_version` 从 5 升级到 6；
- 旧字段（`branch_*`、`d_core`、`quality`）保留为诊断，不参与主分；
- `ScoreResult` 必须可缓存在 `CachedGeneration` 中。

### 3.5 复杂度

| 步骤 | 复杂度 | 说明 |
| --- | --- | --- |
| R1 表 / `Latest` / `slack` | `O(F·V·T)` | 多项式 |
| `H` | `O(T·4^H)` / 策略 | `H ≤ 8`；否则走精确求解 |
| Deception | `O(B·4^d)` / 决策 | `d` 有界；`B` 分支数 |
| Cuts / Contention / L_tight | `O(F·V·T + T)` | 复用表 + 精确重放 |
| 图扩散 | `O(K·(V+E))` / 时间层 | `K` 固定迭代 |
| 公平性 AUC | `O(B log B)` | 排序 |
| PCHIP 拟合 | `O(k)`（k=5）；运行时 `O(log k)` | 离线拟合 |

设计/验收文档只使用上述复杂度，不使用毫秒或内存占用作为算法质量指标；墙钟只保留为运行时熔断。

## 5. 风险与待确认

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `H` 计算成本高 | 每个候选评分变慢 | 阶梯 + 记忆化；`H > 8` 直接记 `∞` 或用求解状态数替代 |
| `H_witness` 只是上界 | 评分可能高估难度 | 标记 `h_is_upper_bound`；生成时可用多路线取最小 |
| 基线扣除压缩分数 | 分布集中在低分段 | 重新校准锚点；必要时对 `D_interaction` 做单调变换 |
| 公平性阈值 / 扩散尺度 | 拒绝过多或放过隐藏陷阱 | 人工回测，调 `σ`、`θ_A`、`θ_F` |
| 锚点非单调 | 拟合无意义 | 先修指标；禁止用拟合掩盖倒挂 |
| 人工体感差异 | 分数排序不符 | 用户试玩校准；保留诊断字段定位原因 |

**待确认：**

1. 5/15/30/40/75 是否就是 L1–L5 的映射；若有误需改锚点表。
2. 校准默认用 `fit`（平滑、允许偏离锚点）还是 `interpolate`（精确过锚点）。
3. 档位边界与是否使用模糊隶属度。
4. `H` 的阶梯与 `H > 8` 的替代口径。
